# Оформление и помощь ИИТ

## Экраны и запуск

- `/#/landing` — «О проекте»; `/#/help` — помощь; `/#/login` — существующая форма Moodle; `/#/admin` — админка. Также поддерживается `/admin` при наличии SPA fallback на хостинге.
- При открытии `/` сохранённая студенческая сессия сразу открывает расписание. Без сессии показывается лендинг. Прямые ссылки на защищённые разделы показывают прежнюю форму входа и сохраняют целевой экран.
- `/?message=12` открывает сообщение, в том числе после входа. Hash-маршруты сохраняют origin и остальные query-параметры, работают с Back/Forward и перезагрузкой. Сессии и API не менялись.
- В FAQ доступен переход к существующей форме обращения без входа: сервер уже поддерживает обращения по токену устройства. Это помогает сообщить о проблеме авторизации.
- Группа Moodle имеет приоритет над старой группой в локальном кэше; ручного выбора у авторизованного студента нет.

## Знак и иконки

Использован знак из предоставленного изображения, также полученный со страницы [Moodle ИИТ](https://eu.iit.csu.ru/login/index.php): [файл логотипа](https://eu.iit.csu.ru/pluginfile.php/1/theme_moove/logo/1789820869/logo-iit2%20%281%29.png).
Исходник `assets/iit-logo-source.png` имеет размер 269×71, полезная область 199×51; щит 39×51. Крупного исходника нет, поэтому детализация больших иконок ограничена. Знак не перерисован; на тёмной подложке сохранена белая надпись.

`python scripts/generate_icons.py` (нужен Pillow только для разработки) воспроизводит favicon, Apple/PWA иконки и Android launcher/round/adaptive foreground для пяти плотностей. У maskable и adaptive иконок содержимое находится в безопасной центральной области. Идентификатор приложения и start_url сохранены.

Основной акцент — голубой, тёмная подложка — `#152d42`. Цвета статусов отмен, предупреждений и успешных действий сохранены. Service worker и логика push не менялись, новые PNG входят в precache.

## Повторение проверок

```text
npm ci
npm test
npm run build
npm run cap:sync
```

Для изолированной проверки интерфейса: `python tests/smoke_server.py`, затем открыть `http://127.0.0.1:4175/`. Данные вымышленные, логин и пароль `fixture`. Стенд обслуживает production dist и mock API только на loopback; не обращается к Moodle и рабочей БД. Данные существуют в памяти процесса. Это не проверка настоящего Moodle.

В backend: `.venv/Scripts/python.exe -m pytest -q`. Получено 86 passed, 54 skipped: отсутствует исходный Excel-файл расписания, от которого зависят пропущенные тесты.

Проверены в браузере мобильная ширина 390 px и десктоп, лендинг, поиск/раскрытие FAQ, переход к обращению, сохранённая сессия и повторный запуск, push-ссылка после тестового входа, день/неделя, профиль без выбора группы, домашка, сохранение заметки, подтверждение сообщения, форма обращения, загрузка внешней карты и возврат. После остановки локального сервера проверены перезагрузка оболочки service worker, показ сохранённого расписания и открытие FAQ. Отсутствие сети для запросов заметок и заданий корректно показано ошибками; их офлайн-синхронизация не добавлялась. Проверены размеры иконок, включение PNG в precache, безопасная область Android adaptive и побайтовое совпадение dist с ресурсами после cap sync. Автотесты навигации отдельно проверяют browser/PWA/Capacitor origins, прямые ссылки, замену адреса после входа и Back.

## Ограничения

Настоящий вход в Moodle с учётной записью студента, установка PWA на устройство и доставка Web Push не проверены. В Capacitor проверены ресурсы и cap sync, APK не собирался и на устройстве не запускался. Нативного push нет: его доступность в WebView не гарантируется. На iOS Web Push требует запуска установленной PWA, поддержки ОС/браузера, разрешения и настроенного сервера. FAQ не обещает push обо всех изменениях расписания.
