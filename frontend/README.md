# Фронтенд расписания

React + TypeScript + Vite. Экран студента: расписание своей группы на день и
на неделю. Все данные приходят с бэкенда готовыми — фронт ничего не вычисляет.

## Запуск

```bash
npm install
cp .env.example .env.local     # если бэкенд не на http://localhost:8000
npm run dev                    # http://localhost:5173
```

Бэкенд должен быть запущен и наполнен (см. `../backend/README.md`).
Порт фронта должен быть указан в `CORS_ORIGINS` бэкенда — по умолчанию там
разрешены `http://localhost:5173` и `http://127.0.0.1:5173`.

```bash
npm run build      # сборка в dist/
npm run preview    # посмотреть собранное
```

## Структура

```
src/
  api/
    types.ts     # типы контракта 03-schedule-json.md
    client.ts    # запросы к бэкенду
    queries.ts   # хуки TanStack Query
    cache.ts     # последний ответ и выбранная группа в localStorage
  App.tsx                      # экраны студента и состояние
  ScheduleComponents.tsx       # шапка, карточка пары, день, сетка недели, нижняя навигация
  pages/admin/DemoAdminScreens.tsx   # разметка админки из прототипа, пока не подключена
  styles.css
```

## Что делает приложение

| Экран | Что показывает |
|---|---|
| Выбор группы | курс -> направление -> группа, список приходит из `GET /groups`; выбор сохраняется на устройстве |
| На день | полоса дат недели, пары выбранного дня; по умолчанию открывается сегодня |
| На неделю | сетка по сетке звонков, линия текущего времени, горизонтальная прокрутка |

Переключение недель — кнопками или свайпом по полосе дат, по полям
`week.prev` / `week.next` из ответа бэкенда.

Последний полученный ответ сохраняется в `localStorage`, поэтому расписание
открывается и без сети; при появлении связи данные обновляются.

## Что отображается у пары

Номер пары показывается, только если `slot` не `null` — пара вне сетки
(например, в 19:00) показывается одним временем. Формат пары берётся из
`type.name`, чтобы новые форматы не ломали экран. Подгруппа из Excel
показывается пометкой «1 подгруппа», если она указана.

Статусы временных изменений (`changed`, `cancelled`, `moved_out`, `moved_in`,
`added`) уже поддержаны в вёрстке, но бэкенд на этом этапе всегда присылает
`regular` — изменения появятся на следующем этапе.
