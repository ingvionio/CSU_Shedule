# Фронтенд расписания

React + TypeScript + Vite. Экран студента: расписание своей группы на день и
на неделю. Все данные приходят с бэкенда готовыми — фронт ничего не вычисляет.

## Запуск

```bash
npm install
cp .env.example .env.local     # если бэкенд не на http://localhost:8000
npm run dev                    # http://localhost:5173
```

Бэкенд должен быть запущен и наполнен (см. `../backend/README.md`).
Порт фронта должен быть указан в `CORS_ORIGINS` бэкенда — по умолчанию там
разрешены `http://localhost:5173` и `http://127.0.0.1:5173`.

```bash
npm run build      # сборка в dist/
npm run preview    # посмотреть собранное
```

## Android APK

Проект [Capacitor](https://capacitorjs.com/docs/android) лежит в
`android/`, идентификатор приложения — `ru.csu.schedule`. PWA раздаётся
как сайт, а APK содержит веб-файлы из `dist/` и открывает их в Android
WebView. Обе версии получают данные из FastAPI. Публикация новой PWA-сборки
обновляет веб-версию. Изменения встроенного интерфейса распространяются
с новой сборкой APK, а изменения расписания приходят через API.

Для сборки нужны Node.js 22+, JDK 21 и Android SDK с платформой API 36.
Путь до SDK задаётся через `ANDROID_HOME` или `sdk.dir` в
`android/local.properties`. Собранный пакет устанавливается на Android
7.0+ (minSdk 24).

1. Укажите в `frontend/.env.local` адрес FastAPI, доступный с телефона по
   HTTPS. Например, `VITE_API_URL=https://api.example.org`, где
   `api.example.org` нужно заменить адресом своего сервера. Клиент сам
   добавляет `/api/v1`. Vite подставляет адрес при сборке.
2. Добавьте `https://localhost` в `CORS_ORIGINS` бэкенда, сохранив
   уже разрешённые адреса фронтенда. В Android это локальный origin
   WebView. Относительные запросы `/api/v1` без `VITE_API_URL` попадут
   на этот origin. Прокси Vite работает в режиме разработки веб-версии.
3. Для push зарегистрируйте Android-приложение `ru.csu.schedule` в Firebase
   и положите его `google-services.json` в `frontend/android/app/`. Файл
   исключён из Git. APK собирается и без него, но push в APK работает
   только с ним и сервисами Google на устройстве. Бэкенду нужен ключ
   сервисного аккаунта **того же проекта** и `FCM_CREDENTIALS_FILE` — см.
   [настройку FCM](../backend/README.md#push-в-android-fcm).
4. Из каталога `frontend` на Windows запустите:

   ```powershell
   npm.cmd ci
   npm.cmd run build:apk
   ```

Скрипт собирает `dist/`, выполняет `cap sync android` и запускает Gradle
`assembleDebug`. Результат — `android/app/build/outputs/apk/debug/app-debug.apk`
относительно `frontend/`. APK предназначен для тестовой установки.
Для обновления версии, которую уже распространяют, нужна отдельная
release-сборка с подписью ключом приложения и увеличенным `versionCode`.

Сессия и локальный кэш APK отделены от браузера. Для получения расписания
и входа на новом устройстве нужен доступ к API. После загрузки клиент
показывает расписание из локального кэша. Web Push реализован для PWA,
в APK используется нативный FCM. В разделе «Сообщения» включите уведомления
и разрешите их показ в системном запросе Android 13+. Уведомления приходят
в канал «Сообщения»; нажатие открывает сообщение. При открытом приложении
обновляется инбокс без системного уведомления. При следующем запуске токен
доставки обновляется автоматически. Huawei/Honor без сервисов Google пока
не поддерживаются.

## Структура

```
src/
  api/
    types.ts     # типы контракта 03-schedule-json.md
    client.ts    # запросы к бэкенду
    queries.ts   # хуки TanStack Query
    cache.ts     # последний ответ и выбранная группа в localStorage
  App.tsx                      # экраны и состояние
  ScheduleComponents.tsx       # шапка, карточка пары, день, сетка недели, нижняя навигация
  pages/CampusMap.tsx          # встроенный навигатор map.csu.ru
  pages/admin/AdminLogin.tsx       # вход администратора
  pages/admin/AdminSchedule.tsx    # временные изменения: сетка недели + диалог изменения
  pages/admin/AdminImports.tsx     # проверка, загрузка и история импортов Excel
  styles.css
```

## Что делает приложение

| Экран | Что показывает |
|---|---|
| Вход | Moodle ИИТ с автоматическим определением группы, сессия сохраняется на устройстве |
| На день | полоса дат недели, пары выбранного дня; по умолчанию открывается сегодня |
| На неделю | сетка по сетке звонков, линия текущего времени, горизонтальная прокрутка |
| Карта | навигатор map.csu.ru: поиск аудиторий, этажи и маршруты |

Карта открывается отдельным экраном через iframe. Нижнее меню расписания
на этом экране скрыто, возврат — стрелкой сверху. При возврате и повторном
открытии карта сохраняет выбранный маршрут. Справа сверху можно открыть
оригинал в отдельной вкладке. Карта требует интернета и доступна даже при
ошибке API расписания; код и данные навигатора загружаются с map.csu.ru.

Переключение недель — кнопками или свайпом по полосе дат, по полям
`week.prev` / `week.next` из ответа бэкенда.

Последний полученный ответ сохраняется в `localStorage`, поэтому расписание
открывается и без сети; при появлении связи данные обновляются.

## Что отображается у пары

Номер пары показывается, только если `slot` не `null` — пара вне сетки
(например, в 19:00) показывается одним временем. Формат пары берётся из
`type.name`, чтобы новые форматы не ломали экран. Подгруппа из Excel
показывается пометкой «1 подгруппа», если она указана.

Изменённые пары помечаются по `status`; под названием выводятся пояснения:
куда/откуда перенесена, что было до замены, комментарий админа.

## Админка

Меню в шапке → «Администрирование расписания» → вход по логину и паролю
(токен хранится на устройстве до истечения). Дальше — сетка недели группы:

* клик по паре — отменить, перенести, заменить аудиторию/преподавателя/время,
  а у уже изменённой пары — откатить изменение;
* клик по пустой клетке — доп. пара;
* режим «Поток» — то же действие сразу для нескольких групп курса.

Все изменения сохраняются на бэкенде (`POST/DELETE /admin/overrides`) и сразу
видны студентам; после ответа все недели перезапрашиваются. Ошибки бэкенда
(пересечение по времени, нет такой пары у группы потока) показываются в диалоге.

Раздел «Загрузка» (`pages/admin/AdminImports.tsx`): «Магистры — по неделям»
(несколько .xlsx или .zip) или «Бакалавры — семестр» (один .xlsx). Сначала
«Проверить» — таблица по файлам (группа, неделя, пары, ошибки с ячейкой), затем
«Загрузить»; ниже — «Последние загрузки».

## Обращения

Вкладка «Вопросы» в нижней навигации: форма (кому, текст,
необязательные имя и контакт) и «Мои обращения» с ответами. Обращения
привязаны к случайному токену устройства (`feedbackToken()` в `api/cache.ts`).

В админке переключатель «Расписание / Обращения»: папки с числом новых,
фильтр по статусу, карточка обращения (ответ, статус, перенос в другую папку,
заметка) и «Адресаты и почта».
