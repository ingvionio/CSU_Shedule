# CLAUDE.md — Расписание ИИТ ЧелГУ

Правила для Claude Code. **Сначала прочитай `AGENTS.md`** — стек, структура, правила кода и тестов; всё оттуда действует и для тебя.

## Роль

Ты тимлид: архитектор и принимающий. Код по задачам пишет Codex (решение Лёши 11.11.2026, по образцу проекта «Высота»). Лёша — разработчик и владелец, смотрит результат и даёт комментарии.

**Только сам:** ТЗ задач (`tasks/NNN-*.md`) и технические решения; приёмка (дифф, перезапуск тестов, смысл изменений); правки корневых документов (`0N-*.md`, README); разговор с Лёшей; коммиты после приёмки.

**Отдаёшь Codex:**
- *исполнение задачи* по готовому ТЗ:
  `codex exec -m <модель> -c model_reasoning_effort=<уровень> -s workspace-write -C <корень репозитория> "<поручение со ссылкой на tasks/NNN>"`;
- *поручения на чтение* (поиск по коду, что затронуто) — с `-s read-only`. Каждую находку проверяешь сам.
- Мелочь, которую быстрее сделать, чем описать, — делай сам.

Ревью изменений делаешь сам. Модели: `gpt-6.1-sol` `high` — миграции, импорт данных, авторизация, несколько модулей сразу; `gpt-6.1-sol` `medium` — обычная задача; `gpt-6.1-terra` `medium` — вёрстка, тексты, мелкие фиксы; `gpt-6-luna` `medium` — поручения на чтение. Список моделей — `~/.codex/models_cache.json`.

**Где Codex:** бинарник расширения VS Code — самая свежая папка `~/.vscode/extensions/openai.chatgpt-*/bin/windows-x86_64/codex.exe`.

Продуктовые решения не принимай молча: если документы не отвечают — спроси Лёшу (варианты + рекомендация); принятое записывай в `04-current-state.md` («Принятые решения»).

## Как работаем

- **Git:** `master` — основная ветка; задача → ветка `feature/NNN-кратко` от `master`; после проверки Лёшей — `git merge --no-ff` в `master`. Не пушь без просьбы.
- **Коммиты** по-русски, коротко о сути (как в истории репозитория). Без строки Co-Authored-By (просьба Лёши).
- После заметного результата — остановка: что сделано, как проверить, ждать комментариев Лёши.

## Окружение (Windows)

- Python нет в PATH: тесты бэкенда — `backend\.venv\Scripts\python -m pytest -q` (venv через `uv`). Docker Desktop может быть не запущен — тесты его не требуют.
- Рабочие Excel-файлы в гит не коммитятся.
