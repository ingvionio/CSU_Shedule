# 010 — Расписание сессии и пересдач

Ветка `feature/session-schedule` (ответвлена от `feature/notifications`:
та ещё не слита и добавляет миграции; сливать по порядку — сначала
уведомления). Голова миграций на старте — `f4c6d8e0a135` (проверь
`alembic heads`).

## Что это

Сессия и пересдачи — **разовые события с датой**, а не повторяющиеся пары.
Образец — опубликованная таблица пересдач ИИТ (разделы «1 курс», «2 курс»…):

| Дата | Время | Группа | Дисциплина | Преподаватель | Аудитория |
|---|---|---|---|---|---|
| 22.09.2026 | 13:15 | БИ-101, ПИ-101 | Экономическая теория | Ткач Е.С. | 122 ⏎ 2 корпус |
| ~~28.09.2026~~ ⏎ 05.10.2026 | 15:15 | БИ-101, ПИ-101 | Информатика и программирование | Николаев И.Е. | ~~132~~ ⏎ 132а ⏎ Внимание! Необходимо подойти к преподавателю до 21.09.26 и получить задание!!! |
| 02.10.2026 | 15:00 | БИ-101, ПИ-101, ПрИ-101,102,103 | История России | Рыбалко А.А. | 114 ⏎ 3 корпус ⏎ Заранее необходимо зайти в 323 кабинет за ведомостью… |
| 12.10.2026 | 11:20 | БИ-101, ПИ-101, ПрИ-101,102,103 | БЖД | Козырская И.Н. | 307 (11 корпус) ⏎ Все задания… |

(⏎ — перенос строки в ячейке, ~~зачёркнуто~~ — прежнее значение.)

## Решения (Лёша, 21.11.2026)

1. Одна сущность для сессии и пересдач, вид `session` | `retake`.
2. Ввод — **и загрузкой Excel, и вручную в админке**, на равных.
3. Студент видит сессию **внутри экрана «Расписание»**: третий режим рядом
   с «На день» / «На неделю». В недельное и дневное расписание события
   не встраиваются (контракт `03-schedule-json.md` не меняется).
4. Группы в таблице — короткие имена: `ПИ-101` = `ИТ1-ПИб-11`
   (`<направление>-<курс>0<номер>` → `ИТ<курс>-<направление>б-<курс><номер>`).

## Требования

### 1. Модель (одна миграция)

`exam_events`:

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | int PK | |
| `semester_id` | FK `semesters` CASCADE, index | семестр, к которому относится (активный при создании) |
| `kind` | varchar(16) CHECK `session`/`retake` | |
| `date` | date | |
| `start_time` | time NULL | время может быть не указано |
| `subject` | varchar(300) | дисциплина текстом, как в таблице («Ин.язык») — не справочник `subjects` |
| `teacher` | varchar(200) NULL | |
| `room` | varchar(200) NULL | аудитория/корпус одной строкой: «122, 2 корпус», «307 (11 корпус)» |
| `note` | text NULL | примечание для студентов |
| `cancelled` | bool, default false | отменено (показывается зачёркнутым) |
| `original_date`, `original_start_time`, `original_room` | NULL | значения до правки (зачёркнутые); NULL — поле не меняли |
| `source` | varchar(16) CHECK `import`/`manual` | |
| `import_id` | FK `exam_imports` SET NULL, NULL | |
| `created_at`, `updated_at` | timestamptz | |

`exam_event_groups` (event_id FK CASCADE, group_id FK CASCADE, PK обоих) —
событие у нескольких групп сразу.

`exam_imports`: id, semester_id, kind, file_name, events_count,
`warnings` JSON (`[{sheet, row, column, text, reason}]`), uploaded_by,
uploaded_at.

Индексы под выборки: события группы по дате (через связь), события
семестра по виду и дате.

### 2. Разбор файла — чистый модуль `app/services/exam_parser.py`

На вход байты `.xlsx`, на выход dataclass'ы строк и список предупреждений;
БД не трогает (правило 2 из `AGENTS.md`).

- Любое число листов; на листе — любое число таблиц. Таблица начинается со
  строки шапки, где есть столбцы «Дата», «Время», «Группа», «Дисциплина»,
  «Преподаватель», «Аудитория» (порядок любой, регистр/пробелы не важны,
  допускаются «Группы», «Ауд.»). Строки до шапки («1 курс») пропускаются.
  Пустая строка таблицу не обрывает; новая шапка начинает новую таблицу.
- Книгу читать с `rich_text=True`, чтобы видеть **зачёркивание** — и у всей
  ячейки (`font.strike`), и у отдельных фрагментов (`CellRichText`).
  Зачёркнутый текст — прежнее значение, незачёркнутый — действующее.
- **Дата:** дата Excel или текст `дд.мм.гггг` / `дд.мм.гг`. Действующая —
  незачёркнутая; зачёркнутая → `original_date`.
- **Время:** время Excel или `ЧЧ:ММ` / `Ч.ММ`; пусто — `None`. Зачёркивание —
  так же (`original_start_time`).
- **Группы:** через запятую; голый номер наследует направление предыдущего:
  `ПрИ-101,102,103` → `ПрИ-101`, `ПрИ-102`, `ПрИ-103`; `ПрИ-101, 102` →
  `ПрИ-101`, `ПрИ-102`. Парсер возвращает короткие имена, сопоставление с БД
  — в импортёре.
- **Аудитория:** незачёркнутые строки ячейки делятся на аудиторию и
  примечание. Строка — аудитория, если она короткая (≤ 30 символов) и
  содержит цифру либо слово «корпус»/«онлайн»/«ауд»; иначе — примечание.
  Строки аудитории склеиваются через «, » («122, 2 корпус»), строки
  примечания — пробелом. Зачёркнутая аудитория → `original_room`.
- **Дисциплина, преподаватель** — текст без лишних пробелов; переносы строк
  внутри ячейки → пробел.
- Строка без даты или без дисциплины — предупреждение «не разобрано», строка
  пропускается. Полностью пустая строка — без предупреждения.

### 3. Импорт `app/services/exam_importer.py`

- Сопоставление групп: сначала точное совпадение с `groups.name` после
  нормализации (регистр, пробелы, дефисы); иначе правило из решения 4
  (`ПИ-101` → `ИТ1-ПИб-11`, `ПрИ-102` → `ИТ1-ПрИб-12`, `БИ-201` →
  `ИТ2-БИб-21`). Не нашлась — предупреждение «группа не найдена: ПИ-105»,
  остальные группы строки остаются; строка без единой группы пропускается.
- **Атомарно** (правило 3): загрузка вида K в активном семестре **заменяет
  все события вида K, пришедшие из загрузок** (`source = import`); ручные
  (`source = manual`) не трогает. Всё в одной транзакции.
- Режимы как у других загрузок: проверка (без записи; отчёт — строки,
  предупреждения, сопоставление групп) и применение.

### 4. API

Методист (`require_admin`), префикс `/admin/exams`:

- `POST /admin/exams/import?kind=session|retake&apply=false|true` — файл;
  ответ: число событий, предупреждения, список «короткое имя → группа»;
- `GET /admin/exams/imports` — история загрузок;
- `GET /admin/exams?kind=&group_id=&course=` — события (с группами);
- `POST /admin/exams` — создать вручную (`source = manual`), группы списком id;
- `PATCH /admin/exams/{id}` — правка. При изменении `date`/`start_time`/`room`
  в `original_*` сохраняется значение **до первой правки** (что студенты
  видели изначально); если новое значение совпало с исходным — `original_*`
  очищается. Остальные поля меняются без истории.
- `POST /admin/exams/{id}/cancel`, `POST /admin/exams/{id}/restore`;
- `DELETE /admin/exams/{id}`.

Студент (публично, как расписание):

- `GET /groups/{group_id}/exams` →
  ```jsonc
  { "group": {"id": 1, "name": "ИТ1-ПИб-11"},
    "kinds": ["session", "retake"],          // какие виды есть у группы
    "events": [{
      "id": 12, "kind": {"code": "retake", "name": "Пересдача"},
      "date": "2026-10-05", "start_time": "15:15",
      "subject": "Информатика и программирование", "teacher": "Николаев И.Е.",
      "room": "132а", "note": "Внимание! …",
      "groups": ["ИТ1-БИб-11", "ИТ1-ПИб-11"],
      "status": "changed",                    // regular | changed | cancelled
      "change": {"date": "2026-09-28", "start_time": null, "room": "132"},
      "is_past": false, "days_left": 3
    }] }
  ```
  Сортировка по дате и времени — на сервере; `is_past`/`days_left` считает
  сервер по текущей дате (правило 1). Отменённые остаются в списке.

Новые схемы — в `app/schemas/`, роутер — `app/api/v1/exams.py`.

### 5. Фронт

**Студент** (экран «Расписание»): переключатель «На день / На неделю» →
«На день / На неделю / Сессия». Режим «Сессия»:
- если у группы оба вида — переключатель «Сессия / Пересдачи», иначе без него;
- список, сгруппированный по датам («5 октября, пн»), ближайшие сверху; у
  ближайших — «через N дней» / «завтра» / «сегодня»;
- карточка: время, дисциплина, преподаватель, аудитория, примечание
  (выделено); прежние дата/время/аудитория — зачёркнуты рядом с новыми, как
  в образце; отменённое — зачёркнуто с пометкой «отменено»; «вместе с …» —
  другие группы, если есть;
- прошедшие — свёрнуты в конце («Прошедшие (N)»);
- пусто — «Расписание сессии пока не опубликовано»;
- данные — через TanStack Query и кэш, как у недели (офлайн).

**Методист**: раздел «Сессия» в админке:
- загрузка: выбор вида, файл, проверка (таблица строк, предупреждения,
  сопоставление групп), применение; предупреждение, что загрузка заменит
  ранее загруженные события этого вида (ручные останутся);
- список событий с фильтрами (вид, курс, группа); добавить, изменить,
  отменить/вернуть, удалить; в списке видны прежние значения и источник.

Стили — в `styles.css` рядом с похожими. Фронт ничего не вычисляет.

### 6. Тесты

Excel-книги строить в тесте openpyxl во временной папке, **с зачёркиванием**
(и целой ячейки, и фрагмента через `CellRichText`/`TextBlock`).

- парсер: шапка в любом порядке и после «1 курс»; несколько таблиц на листе;
  разбор групп (`ПрИ-101,102,103`, `ПрИ-101, 102`, `БИ-101, ПИ-101`);
  зачёркнутая/новая дата; зачёркнутая/новая аудитория; аудитория + корпус +
  примечание; дата и время как значения Excel и как текст; строки без даты.
- импорт: сопоставление (точное, по правилу, не найдена); атомарность и
  замена только `import` этого вида; ручные остаются; проверка ничего не пишет.
- API: права (студенческий токен и аноним на `/admin/exams` — 401/403);
  правка с `original_*` по правилам; отмена/возврат; выдача студенту —
  сортировка, `status`, `change`, `is_past`, `days_left` (с подменой «сегодня»).
- `npm run build` зелёный.

## Вне задачи

- встраивание событий в недельное/дневное расписание;
- push при изменении экзамена (можно потом через рассылку);
- виды «экзамен/зачёт/консультация» внутри сессии (в таблице их нет).

## Вопросы к архитектору

- Как хранить исходное пустое время/аудиторию при правках? `original_* = NULL` уже означает отсутствие правки. Предложен дополнительный JSON-признак `original_empty_fields`; ответ ожидается.

**Ответ архитектора (21.11.2026):** три колонки `original_*` заменяются
одним JSON-полем `original` (`{"start_time": null, "room": "132"}`): наличие
ключа — поле меняли, значение — каким оно было, в том числе пустым. Делается
в задаче 012 правкой миграции `f5d7e9a1b246` (на прод ещё не выкладывалась).

## Отчёт

Реализована однозначная часть задачи: модель и миграция, парсер, атомарный
импорт, API, студенческий режим «Сессия» и раздел методиста. Открытый вопрос
об истории исходно пустых полей приведён выше; дополнительное поле без
решения архитектора не добавлялось.

Что сделано:

- Модель: `exam_events`, `exam_event_groups`, `exam_imports`; ограничения
  вида и источника, внешние ключи, индексы, временные отметки.
- Одна миграция `f5d7e9a1b246` после проверенной головы
  `f4c6d8e0a135`; текущая единственная голова — `f5d7e9a1b246`.
- Чистый парсер читает байты с `rich_text=True`, несколько листов/таблиц,
  произвольный порядок заголовков, даты/время Excel и текстом, группы с
  наследованием направления, зачёркивание ячейки и отдельных фрагментов.
  Аудитория, корпус и примечание разделяются по правилам задачи;
  неразобранные строки возвращаются предупреждениями с координатами.
- Импорт сопоставляет группы сначала точно после нормализации, затем по
  правилу короткого имени. Проверка не пишет в БД. Применение одной
  транзакцией заменяет только `source=import` нужного вида и семестра,
  сохраняет ручные события, историю и предупреждения. Проверен откат
  удаления и записи истории при исключении.
- Админское API защищено `require_admin`: загрузка/проверка, история,
  фильтры, создание, PATCH, отмена/возврат, удаление. Для непустых исходных
  даты/времени/аудитории сохраняется первая версия, возврат к ней очищает
  историю; импортированная история также сохраняется при ручной правке.
- Публичная выдача группы отсортирована на сервере; вид, статус, изменения,
  прошедшие события и число дней рассчитываются сервером. Контракт недели
  не менялся.
- Студент: третий режим расписания, выбор вида при наличии обоих, даты,
  карточки с прежними значениями и примечаниями, другие группы, свёрнутые
  прошедшие, пустое состояние, TanStack Query и localStorage для офлайна.
- Методист: отдельный раздел «Сессия», предпросмотр строк, предупреждений
  и сопоставления групп перед применением, предупреждение о замене,
  история загрузок, фильтры и ручные действия. Изменения обновляют кэш
  студента, список событий и историю.

Сомнения/ограничения:

- Требуется ответ на вопрос выше: исходное `NULL` времени/аудитории
  невозможно представить отдельно от «не меняли» указанными колонками.
  Например, цепочка `NULL → 13:15 → 15:15` без дополнительного признака

  незавершённый случай истории, не покрытый утверждением о корректности

- Не проверены реальный браузер/устройство и реальный PostgreSQL;

- Уже существовавшие изменения `04-current-state.md`, `.claude/`,
  `_claude_test/`, а также появившиеся во время работы задачи 011/012
