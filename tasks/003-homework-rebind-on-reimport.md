# 003 — Домашка не теряет пару при перезагрузке расписания

| | |
|---|---|

| Документы | `tasks/001-masters-weekly-import.md`, `tasks/002-admin-schedule-upload.md`, `04-current-state.md` |

| Статус | поставлена |

## Проблема

Групповая домашка (`group_homework`) привязана к паре через `lesson_id` (FK на `lessons.id`, `ondelete="SET NULL"`) и `lesson_date`. Фронт показывает домашку в окне и на карточке пары по ключу `` `${lesson_date}:l-${lesson_id}` `` (`frontend/src/App.tsx` ~114, ~568).

Любая перезагрузка расписания удаляет старые пары и создаёт новые с новыми `id`:
- понедельная (`weekly_importer.import_weekly`) — пары группы за неделю;
- семестровая (`importer.import_workbook`) — все пары групп книги.

`lesson_id` домашки становится `NULL`: задание остаётся в «Заданиях на эту неделю», но пропадает из окна и с карточки пары — даже если в новом файле пара та же самая. Проверка перед загрузкой (dry-run, задача 002) об этом не говорит.

## Решения архитектора

1. **Перепривязка после замены.** Перед удалением старых пар запомнить для каждой затронутой домашки (не архивной и архивной — всех, у кого `lesson_id` среди удаляемых): `lesson_date` и «отпечаток» старой пары — `start_time`, `end_time`, `subject_id`, `subgroup`. После вставки новых пар найти для каждой новую пару **той же группы**, которая **идёт в `lesson_date`** (используй `schedule.lesson_occurs_on` — чётность и срок действия), и выбрать:
   1. совпадают `start_time` и `subject_id` (и `subgroup`, если у старой он был) → привязать;
   2. иначе: в этот день у группы ровно одна новая пара с тем же `subject_id` → привязать (пару сдвинули по времени);
   3. иначе — оставить `lesson_id = NULL` («отвязана»). `lesson_date`, `subject_id` домашки и прочие поля **не менять**.
   Перепривязка — в той же транзакции, что и замена пар; `version`/`updated_by`/`updated_at` домашки не трогать (это не правка пользователя).
2. **Где.** Общая функция в `app/services/homework.py` (или отдельный модуль рядом), вызывается из обоих импортёров. В `import_workbook` — до `session.commit()`. Правила импорта из 001/002 не менять.
3. **Отчёт.** В `WeeklyImportReport` и `ImportReport` — счётчики `homework_rebound` и `homework_unbound`. В CLI-итогах (`import-weekly`, `import-excel`) — «домашка: перепривязано N, отвязано M» (печатать, только если N+M > 0). В ответах API загрузки (`WeeklyImportOut`, `SemesterImportOut`) — те же два поля.
4. **Проверка (dry-run).** Для weekly dry-run уже идёт в откатываемой транзакции — счётчики получатся сами. Для semester dry-run (там только разбор) — посчитать, **сколько домашек привязано к парам, которые будут заменены** (`homework_affected`), без попытки предсказать перепривязку; в интерфейсе: «Домашка у заменяемых пар: N — будет перепривязана к тем же парам, где они совпадут».
5. **Фронтенд** (`pages/admin/AdminImports.tsx`): в итоге проверки и загрузки показывать строку про домашку, если числа ненулевые; `homework_unbound > 0` — заметно (как предупреждение): «M заданий останутся без пары — они видны в «Заданиях на неделю», но не в окне пары».
6. **Только своя группа.** Домашка других групп и пары других групп не участвуют ни при каких условиях.

## Тесты (до кода)

Используй генератор книг из `tests/test_weekly_import.py` и фикстуры из `tests/test_homework.py`.
- Weekly: домашка на пару недели 8 → перезагрузка той же книги → `lesson_id` указывает на новую пару с тем же временем и предметом; отчёт `homework_rebound=1`; через API расписания + API домашки ключ `дата:l-<id>` совпадает с парой дня.
- Пару сдвинули по времени (тот же предмет, тот же день, одна такая пара) → перепривязана.
- В новом файле этой пары нет → `lesson_id = NULL`, `homework_unbound=1`, задание по-прежнему в списке недели группы.
- Два кандидата (сдвоенная пара с тем же предметом, старое время не совпало ни с одной) → не угадываем, `unbound`.
- Сдвоенная пара 7+8 одного предмета, домашка на 8-ю, время не менялось → привязана к 8-й, не к 7-й.
- Домашка другой группы / другой недели — не тронута (тот же `lesson_id`).
- Weekly dry-run: счётчики в ответе есть, в базе `lesson_id` не изменился.
- Semester (`import_workbook`): перепривязка работает — если без реального Excel не собрать, вынеси перепривязку в функцию и протестируй её на парах, заведённых в тесте; сквозной тест с реальным Excel пропускается без файла.
- `version`, `updated_by`, `updated_at` домашки после перепривязки не изменились.
- Все прежние тесты зелёные; `npm run build` проходит.
