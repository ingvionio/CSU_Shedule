## Проблема (замечание Степы, 12.11.2026)

Админка → «Расписание» → «Поток»:
1. **В списке «Группы потока» появились магистры** (`МБИ 101` среди `ИТ1-БИб-11`, `ИТ1-ПИб-11`…). Список строится только по курсу (`AdminSchedule.tsx`, `streamGroups = groups.filter(group.course === primaryGroup.course)`), а у магистров 1 курса `course = 1`.
2. **Сетка показывает расписание одной «основной» группы** (`useSchedule(adminGroupId)` в `App.tsx`), остальные отмеченные группы на неё не влияют. Ожидание: **в режиме потока видны только пары, которые есть у всех выбранных групп** — именно к ним применимо «то же действие сразу для нескольких групп».

## Решения архитектора

1. **Уровень обучения группы.** В ответ `GET /api/v1/groups` (`GroupOut`) добавить `level: "bachelor" | "master"`, вычисляемый на бэкенде из направления: магистерские направления — те, что в `groups.py` (`МПрИ`, `МИТ`, `МПИ`, `МБИ`); вынести их в константу `MASTER_DIRECTIONS` и функцию `level_of(direction)`. Без миграции. Неизвестное направление → `bachelor`.
2. **Список групп потока** = группы того же курса **и того же уровня**, что основная. Магистры с бакалаврами в одном потоке не встречаются никогда.
3. **Неделя потока считается на сервере** (правило AGENTS: фронт не сводит расписания сам). Новый эндпоинт админки:
   `GET /api/v1/admin/stream-schedule?group_ids=1&group_ids=2[&week=N]` (`require_admin`; 2+ группы; все — один курс и уровень, иначе 422 с русским текстом; первая в списке — основная).
   Ответ — тот же формат, что неделя группы (`WeekScheduleOut`: `week`, `semester`, `days[].lessons[]`), где в днях **только общие пары**:
   - собрать неделю каждой группы существующей сборкой (`schedule.build_week_schedule`);
   - **ключ совпадения** для пар из постоянного расписания — как у `overrides._matching_lessons`: дата исходной пары + время начала исходной пары + предмет исходной пары (у `changed`/`cancelled`/`moved_out` — исходные значения, не изменённые; у `moved_in` — по `moved_from`); для `added` — общий `batch_id` изменения (одно действие на поток);
   - пара попадает в ответ, если ключ есть **у всех** выбранных групп; в ответе — элемент **основной** группы (его `id` и `change.override_id` используются формой изменения и отката, как сейчас);
   - новое поле элемента `stream_diff: list[str] | null` — если у групп эта пара выглядит по-разному (статус, время, аудитория, преподаватель, формат), список коротких русских пометок вида `«ИТ1-ПрИб-12: ауд. 326»`, `«ИТ1-ПИб-11: отменена»`; иначе `null`. В обычной неделе группы поле не заполняется (`null`).
   - Заметки, домашка и `note_key` в ответе потока не нужны (`note_key: null`).
4. **Фронтенд** (`AdminSchedule.tsx`, `App.tsx`, `api/queries.ts`, `api/types.ts`):
   - в режиме «Поток» сетка берёт данные из `stream-schedule` по выбранным группам (новый хук; ключ кэша включает отсортированные `group_ids` и неделю; инвалидировать вместе с расписанием после создания/отката изменения);
   - над сеткой подпись: «Показаны только пары, общие для всех выбранных групп (N)»; если отмечена одна группа — обычная неделя этой группы и подпись не нужна;
   - карточка пары с `stream_diff` — заметная пометка «У групп по-разному» и строки из `stream_diff` во всплывающей подсказке и в окне пары;
   - режим «Одна группа» — без изменений.
5. Создание изменений для потока (`POST /admin/overrides` с несколькими `group_ids`) и откат `batch=true` **не меняются**.

## Тесты (до кода)

Бэкенд (группы и пары заводи в тесте напрямую, как в `tests/test_overrides.py`; реальный Excel не нужен):
- `GET /groups`: `МИТ 101` → `level=master`, `ИТ1-ПрИб-11` → `bachelor`.
- Две группы с общей парой (тот же день, время, предмет) и у каждой своя уникальная → в ответе потока только общая; `id` — пары основной группы.
- Общая пара, у второй группы другая аудитория → пара есть, `stream_diff` содержит пометку про аудиторию второй группы.
- Изменение потоком (`replace` на обе группы одним запросом) → пара в ответе со статусом `changed` у основной, без `stream_diff` (если итог одинаков).
- Отмена только у одной группы → пара есть, `stream_diff` содержит «… отменена».
- Доп. пара потоком (`add` на обе группы) → есть; доп. пара только у одной → нет.
- Группы разного курса или бакалавр + магистр → 422; одна группа → 422 (для одной группы есть обычный эндпоинт); без токена → 401.
- Неделя без общих пар → дни есть, `lessons` пустые.
- Прежние тесты зелёные.

Фронтенд: `npm run build` проходит; проверка рендеринга — пометка «У групп по-разному» и подпись над сеткой.
