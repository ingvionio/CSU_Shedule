# 005 — Два критических исправления авторизации Moodle

## Поручение

Пользователь поручил исправить первые две ошибки из обзора интеграции с eu.iit.csu.ru:

1. Префикс логина `mock_` включает фиктивный вход при `MOODLE_MOCK=False`.
2. Отсутствующий Moodle ID заменяется на `unknown`, из-за чего разные пользователи объединяются.

## Вопросы к архитектору

Неясностей в объёме исправлений нет. Уже объединённые профили и выданные ранее JWT требуют отдельного решения архитектора; автоматическое восстановление данных в поручение не входит.

## Отчёт

- В `backend/app/services/moodle.py` mock-вход разрешён только настройкой `MOODLE_MOCK`.
- Отсутствие Moodle ID в профиле вызывает русскоязычную ошибку 502 до определения группы и сохранения пользователя; общий ID `unknown` больше не подставляется.
- Сервис сохранения дополнительно отклоняет пустой ID и `unknown` до поиска пользователя и любых изменений данных.
- Исправлены аннотация возвращаемого значения и docstring `get_profile_info`: метод возвращает четыре значения.
- В `backend/tests/test_moodle.py` добавлены проверки префикса `mock_` при выключенном mock-режиме, чтения ID из URL и ссылки, отказа при отсутствии ID, отсутствия JWT при таком отказе и сохранности существующего пользователя с пустым ID/`unknown`.
- До изменения сервиса регрессионная выборка дала 3 failed, 2 passed; после исправления — 5 passed.
- Подготовлена локальная `.venv` из существующего `requirements-dev.txt`. Новых зависимостей проекта и миграций нет. Фронтенд не менялся. Коммитов нет.
