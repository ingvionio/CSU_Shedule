# 012 — Файл сессии в формате сетки («Расписание промежуточной аттестации»)

Ветка `feature/session-schedule`. Начинать после приёмки 010 (модель, импорт,
API, экраны). 010 разбирает таблицу пересдач (строка = событие); настоящий
файл сессии ИИТ устроен иначе — его и разбирает эта задача. Загрузка вида
`session` идёт через новый парсер, `retake` — через парсер таблицы из 010.

Рабочий файл в репозиторий не кладём; для тестов строим маленькие книги
openpyxl с той же раскладкой.

## Требования

### 1. Парсер `app/services/session_grid_parser.py` (чистый модуль)

- Каждый лист — отдельно (обычно лист на курс). Строка групп — первая
  строка, где в столбцах правее A стоят имена групп (`ПИ-301`, `ПрИ-302`,
  `МИТ-101`…: буквы, дефис/пробел, цифры). Столбцы групп — от неё.
- **Даты** — в столбце A: `15 ИЮНЯ (ПН.)`, `01 ИЮЛЯ (СР.)` (регистр любой,
  день недели в скобках необязателен, лишние пробелы допустимы); также дата
  Excel. **Года нет** — берётся из строки шапки вида «… 2025 - 2026 учебного
  года»: месяцы сентябрь–декабрь → первый год, январь–август → второй. Шапки
  нет — год по активному семестру (тот же принцип от его `start_date`) и
  предупреждение.
- **Событие** в столбце группы — строки `дата−1`, `дата`, `дата+1` (дата
  стоит в средней строке):
  1. строка 1 + строка 2 — название; в строке 2 в конце вид в скобках:
     `(КОНСУЛЬТАЦИЯ)`, `(ЭКЗАМЕН)`, `(ЗАЧЁТ)`/`(ЗАЧЕТ)`,
     `(ДИФФЕРЕНЦИРОВАННЫЙ ЗАЧЁТ)`/`(ДИФ. ЗАЧЁТ)`; текст строки 2 без скобок
     дописывается к названию через пробел (может быть пустым);
  2. строка 3 — через запятую: время (`15:00`, `9.40`), аудитория
     (часть, начинающаяся с `АУД.`/`АУД`; `АУД. 132А` → `132а`, `АУД. А-13` →
     `А-13`), остальное — преподаватели (склеить через «, »). Время и
     аудитория необязательны.
  Нет вида в скобках — вид `other` и предупреждение. Пустой блок — не событие.
- Одинаковые события (дата, вид, название, преподаватели, время, аудитория)
  в разных столбцах — **одно событие для нескольких групп**.
- Подписи внизу и шапка «УТВЕРЖДАЮ» событиями не являются.
- Зачёркивание — как в 010 (`rich_text=True`): зачёркнутое → прежнее
  значение (`original_*`). В образце его нет, но методист может так править.

### 2. Регистр

Файл набран заглавными. Сохранять в читаемом виде:
- **преподаватели**: `ШЕПТАЛИН А.Г.` → `Шепталин А.Г.`, двойные фамилии через
  дефис — обе части с заглавной;
- **название**: с заглавной только первая буква, остальные строчные, кроме
  аббревиатур из словаря (`ИТ`, `ИС`, `БД`, `СУБД`, `ОС`, `ЭВМ`, `ИИ`, `ВКР`,
  `БЖД`, `1С`, `UML`, `SQL`, `IT`…; латиница в верхнем регистре остаётся как
  есть) и `ПО`, когда это последнее слово («… жизненным циклом ПО»).
  Пример: `УПРАВЛЕНИЕ ИТ-ПРОЕКТАМИ И ЖИЗНЕННЫМ ЦИКЛОМ ПО` →
  `Управление ИТ-проектами и жизненным циклом ПО`;
- **аудитория**: буквы после цифр — строчные (`132А` → `132а`), буква перед
  дефисом — как есть (`А-13`).
Методист может поправить текст в админке.

### 3. Вид события внутри сессии

Новое поле `exam_events.event_type` (миграция): `consultation` | `exam` |
`credit` | `graded_credit` | `other`, NULL для пересдач из таблицы 010 (там
вида нет). В API студенту — `type: {code, name}` («Консультация», «Экзамен»,
«Зачёт», «Дифф. зачёт»), в админке — выбор при ручном создании/правке.

На фронте у студента: вид — пометкой на карточке; консультация визуально
спокойнее экзамена (экзамен — акцент).

### 3а. История правок — одно поле `original` (ответ на вопрос из 010)

Колонки `original_date`, `original_start_time`, `original_room` заменить
одним JSON-полем `exam_events.original` (NULL — правок нет). Ключ есть —
поле меняли; значение — каким было до первой правки, **в том числе `null`**
(время/аудитория изначально не были указаны). Возврат к исходному значению
удаляет ключ; пустой словарь → NULL. Делать **правкой миграции
`f5d7e9a1b246`** (на прод не выкладывалась) вместе с `event_type`, отдельной
миграции не нужно. Парсеры (зачёркнутое) пишут туда же. В API студенту
`change` по-прежнему `{date, start_time, room}`, плюс список изменённых полей
`change.fields`, чтобы фронт отличал «было пусто» от «не меняли».

### 4. Импорт

`kind = session` → этот парсер, `kind = retake` → парсер таблицы из 010.
Сопоставление групп и атомарная замена — как в 010. В отчёте проверки —
листы, найденные группы по каждому листу, год, события.

### 5. Тесты

Книга как в образце (шапка, строка групп, тройки строк, дата без года):
- год из шапки (июнь → второй год, декабрь → первый); без шапки —
  по семестру + предупреждение;
- консультация/экзамен/зачёт; название из двух строк и из одной;
- строка 3: с временем и аудиторией, только время, только преподаватели,
  два преподавателя;
- одно событие у двух групп; разные события в один день у разных групп;
- регистр (преподаватель, название с `ИТ-` и `ПО` в конце, аудитория);
- подписи и шапка не становятся событиями;
- два листа (два курса) в одной книге.
