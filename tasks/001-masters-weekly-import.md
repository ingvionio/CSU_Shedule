## Цель

Магистры 1 курса получают расписание не одним файлом на семестр, а **отдельным Excel на каждую неделю и группу** (архив `Понедельное_расписание_занятий_для_магистров_1_курса_*.zip`). Нужна команда, которая заливает такие файлы в базу так, чтобы магистры видели свои пары в приложении, а расписание бакалавров при этом не пострадало. Новые недели приходят по мере составления — их догружают той же командой.

## Формат файла (проверено на всех 44 файлах архива)

Одна книга = одна группа × одна неделя, один лист с именем `N неделя` (N — номер учебной недели, совпадает с неделями семестра в приложении).

| Ячейка | Что |
|---|---|
| A1–A3 | шапка («РАСПИСАНИЕ ЗАНЯТИЙ», семестр, институт) — пропускаем |
| A5 | `ЗАНЯТИЯ 19.10.26 - 24.10.26` — даты недели |
| C6 (объединена C6:D6) | название группы: `МИТ 101`, `МПрИ 101`, `МБИ 101`, `МПИ 101` |
| столбец A, объединения по строкам | день: `ПН ВТ СР ЧТ ПТ СБ` |
| столбец B, объединения по строкам | номер пары; **диапазон объединения B = строки этой пары** |
| столбец C (объединена C:D построчно) | текст пары: по одной строке на ячейку |
| строки ниже таблицы, только столбец A | сноски: `* занятия проходят через неделю по средам` |

Содержимое блока пары (строки C в диапазоне объединения B) — ровно одна из форм:

1. **Очно:** `ПРЕДМЕТ` / `ФАМИЛИЯ И.О.` / `АУД. 132А`
2. **Дистанционно:** `с использованием дистанционных образовательных технологий` / `https://…` / `ПРЕДМЕТ` / `ФАМИЛИЯ И.О.`
3. **Дистанционно со своим временем:** то же, но первая строка `с 13:10 с использованием дистанционных образовательных технологий`
4. **Нет пары:** пусто, либо `ДЕНЬ САМОСТОЯТЕЛЬНЫХ` / `ЗАНЯТИЙ` (эти две строки могут попадать в соседние блоки — это не пара, отбрасываются целиком).

Формат пары (лекция/практика) в файлах не указан. Пары всегда сдвоены: в будни 7 и 8, в субботу около 13:10 и следующая.

Пример блоков (неделя 8, МИТ 101): `ПТ 7`: строки 39–42 — ДОТ, `https://bbb.csu.ru/…`, `САМОМЕНЕДЖМЕНТ**`, `АНТРОПОВА Л.Г.`; `СБ 4`: строки 48–51 — `с 13:10 с использованием …`, ссылка, `МАШИННОЕ ОБУЧЕНИЕ И АНАЛИЗ ДАННЫХ***`, `ИВАНОВА О.Н.`; `СБ 5`: строки 52–55 — то же без времени.

## Решения архитектора (реализуй так)

1. **Хранение — обычные постоянные пары (`lessons`) со сроком действия в одну неделю**: `week_parity='both'`, `valid_from` = понедельник недели N, `valid_to` = воскресенье недели N (`weeks.monday_of_week`), `week_from = week_to = N`. Схема `lessons` под это не меняется; сборка недели и временные изменения работают как есть.
2. **Название группы** — из C6, пробелы схлопнуть (`МИТ 101`). Если C6 пуст или в нём нет трёхзначного номера — взять из имени файла (`Расписание МИТ-101 1 неделя …` → `МИТ-101`), предпочитая вариант с **трёхзначным** номером; не нашли трёхзначный — ошибка файла (решение Лёши: «выбирай там, где 3 цифры»). Курс — первая цифра номера (`101` → 1).
3. **Направление (поток) магистров — своё**: `МИТ`, `МПрИ`, `МПИ`, `МБИ`. Сейчас `groups.direction_of("МПрИ 101")` вернёт `ПрИ` и магистры попадут в поток бакалавров (рассылка «потоку», изменение «на весь поток»). Расширь `direction_of`: магистерские коды проверяются раньше бакалаврских; бакалавры (`ИТ1-ПрИб-11` → `ПрИ`, `ПИ 201` → `ПИ`, `БИ 301` → `БИ`) не меняются. Уже существующим группам импорт направление проставляет только если оно пустое (как сейчас в `importer.py`) — но для групп, созданных этим импортом, оно обязано быть магистерским.
4. **Звёздочки сносок убираются из названия предмета** (`САМОМЕНЕДЖМЕНТ***` → `САМОМЕНЕДЖМЕНТ`), иначе один предмет станет тремя. Текст сносок файла в базу как отдельная сущность не идёт; в `source_text` пары пиши исходные строки блока (обрезка до 600 символов).
5. **Ссылка на онлайн-занятие — новое поле `lessons.online_url`** (String(500), nullable) + миграция Alembic (`down_revision = "e8c1b2a3d4f5"`). Дистанционная пара: `online_url` = ссылка из блока, `room = None`. Формат пары — `other` («Занятие»).
6. **Время.** Будни: номер пары из B → сетка звонков (`time_slots`). **Номера субботних пар в файлах ненадёжны** (одни и те же занятия у одной группы подписаны 3 и 4, у другой 4 и 5). Правило для дня, где у блока указано своё время `с ЧЧ:ММ`:
   - этот блок: `start_time` = указанное, `end_time` = start + длительность слота, `slot = None` (как пары «с 19:00» у бакалавров); «якорный» номер — слот сетки с ближайшим временем начала (13:10 → 4);
   - следующие блоки этого дня по порядку получают номера якорь+1, якорь+2… и время по сетке (13:10 → следующая пара 5, 15:00–16:30) [П — предварительно, уточняется у методиста];
   - блоки этого дня выше якорного — по номеру из B, как обычно.
7. **Контроль дат.** Даты из A5 должны попадать в неделю N активного семестра (понедельник недели N ≤ начальная дата ≤ воскресенье). Не совпало или не разобралось — ошибка этого файла.
8. **Замена при повторной загрузке — только своё.** Импорт недели N группы G удаляет пары G с `week_from = week_to = N` этого семестра (их изменения удалятся каскадом — посчитай и выведи их число) и создаёт новые. Больше ничего не трогает.
9. **Импорт бакалавров не должен стирать магистров.** Сейчас `import_workbook(..., replace=True)` удаляет **все** пары семестра. Сузь: удалять только пары групп, которые есть в разобранной книге. Поведение для бакалавров в остальном не меняется.
10. **Атомарность:** одна команда — одна транзакция; если хоть один файл с ошибкой — ничего не записывается, команда печатает ошибки всех файлов и выходит с кодом 1. Флаг `--skip-errors` — записать корректные файлы, ошибочные пропустить (и всё равно код 1). Запись `schedule_imports` — одна на запуск, `file_name` — перечень/путь, в `errors` — ошибки и предупреждения.

## Что сделать

- `app/services/weekly_parser.py` — чистый парсер одной книги (путь или байты) → dataclass с группой, номером недели, датами, списком пар (`weekday, slot_label, custom_start, subject, teacher, room, online_url, source_ref, source_text`) и ошибками. Раскладку находить по содержимому, а не по жёстким номерам строк: строка с `ЗАНЯТИЯ dd.mm.yy - dd.mm.yy`, ячейка группы — первая непустая в строке под ней в столбцах C+, дни — объединения в A, пары — объединения в B. Нераспознанный блок (не одна из 4 форм) — предупреждение с адресом ячейки и текстом, пара не создаётся.
- `app/services/weekly_importer.py` (или функции в `importer.py`, если так чище) — запись по решениям 1–3, 5–10; справочники через существующий `_get_or_create`; `ensure_reference_data`.
- `app/cli.py`: `python -m app.cli import-weekly <путь> [<путь> …] [--skip-errors]`; путь — файл `.xlsx`, папка (рекурсивно все `.xlsx`) или `.zip` (распаковать во временную папку; имена внутри zip могут быть не в UTF-8 — на имена не опираться, кроме запасного варианта из решения 2). Вывод по-русски: по каждому файлу «МИТ 101, неделя 8: пар 12» и итог «Файлов: N, групп: G (новых: K), пар: P, удалено изменений: X, ошибок: E».
- `Lesson.online_url` + миграция; `schemas/schedule.py` `LessonOut.online_url: str | None = None`; `services/schedule.py`: обычная пара — из `lesson.online_url`, `replace` — сохраняет ссылку исходной пары, `moved_in` — ссылка исходной пары, `add` — `None`.
- Фронтенд: `api/types.ts` — `online_url: string | null`; карточка пары (`ScheduleComponents.tsx`) и окно пары — если есть `online_url`, показать «Онлайн» вместо аудитории и ссылку-кнопку «Подключиться» (`target="_blank" rel="noopener noreferrer"`). Только `http(s)://` ссылки делать кликабельными. Стили — по образцу соседних элементов.
- `direction_of` — решение 3.

## Тесты (до кода)

Книги для тестов строй openpyxl во временной папке (фикстура-генератор с раскладкой как выше, с объединениями). Реальные файлы в репозиторий не кладём.
- Парсер: все 4 формы блока; звёздочки убраны; ДОТ → ссылка и без аудитории; `ДЕНЬ САМОСТОЯТЕЛЬНЫХ / ЗАНЯТИЙ`, разнесённые по двум блокам, не дают пар; сноски не становятся парами; номер недели из имени листа; даты из A5.
- Группа: из C6; C6 без трёхзначного номера → из имени файла с трёхзначным; нигде нет — ошибка.
- Суббота: блоки `3 (с 13:10)` + `4` и блоки `4 (с 13:10)` + `5` дают одинаковый результат: 13:10–14:40 `slot=None` и 15:00–16:30 `slot=5`.
- Даты A5 не совпадают с неделей N семестра → ошибка файла.
- Импорт: пары создаются со сроком в одну неделю и видны через `GET /api/v1/groups/{id}/schedule?week=N` только в неделе N, с `online_url`; повторный импорт той же недели не плодит дубликаты; импорт недели 9 не трогает неделю 8; повторный импорт удаляет изменение (override), привязанное к паре этой недели, и считает его.
- Пара другой группы (бакалавры, заведённые в тесте напрямую) после `import-weekly` на месте. Сужение удаления в `import_workbook`: пара группы, которой нет в книге, остаётся (если без реального Excel не собрать — вынеси выбор удаляемых пар в функцию и протестируй её; сквозной тест с реальным Excel пусть пропускается без файла, как остальные).
- Атомарность: два файла, один битый → в базе ничего; с `--skip-errors` — корректный записан, код 1.
- `direction_of`: `МПрИ 101`→`МПрИ`, `МИТ 101`→`МИТ`, `МПИ 101`→`МПИ`, `МБИ 101`→`МБИ`; бакалавры как раньше.
- Все прежние тесты зелёные; `npm run build` во `frontend/` проходит.

## Вопросы к архитектору

- Пункт 10 одновременно требует «ничего не записывается» при ошибке пачки и одну запись `schedule_imports` на запуск. Нужен ли отдельный аудит полностью неудачных запусков? Сейчас при полном отказе нет никаких записей, включая журнал; при успешной или частичной загрузке создаётся одна запись с общими ошибками и предупреждениями. Это сохраняет требуемую атомарность.

  **Ответ архитектора:** отдельный журнал неудачных запусков не нужен — ошибки печатаются в консоль, команду запускает человек. Оставляем как есть.
