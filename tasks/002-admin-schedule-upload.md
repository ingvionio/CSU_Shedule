## Цель

Методист загружает расписание сам, без консоли и Docker: в админке новый раздел **«Загрузка»**. Два вида файлов:

1. **Понедельное расписание магистров** — несколько `.xlsx` и/или `.zip` сразу (обычно 4 группы × 1 неделя каждую неделю, иногда целый архив за много недель). Логика — та же, что у `import-weekly` (задача 001).
2. **Расписание бакалавров на семестр** — один `.xlsx` (логика `import-excel`).

Сначала **«Проверить»** — показать, что будет загружено, ничего не записывая; затем **«Загрузить»**.

## Решения архитектора

1. **API** (под существующим `/api/v1/admin`, право — `require_admin`; студентский токен — 401/403 как у остальных админских эндпоинтов):
   - `POST /api/v1/admin/imports/weekly` — `multipart/form-data`: `files` (1..N файлов `.xlsx`/`.zip`), `dry_run: bool` (по умолчанию `true`), `skip_errors: bool` (по умолчанию `false`).
   - `POST /api/v1/admin/imports/semester` — `multipart/form-data`: `file` (один `.xlsx`), `dry_run: bool` (по умолчанию `true`).
   - `GET /api/v1/admin/imports?limit=20` — последние записи `schedule_imports` (id, имя файла, дата, кто, статус, число пар, число ошибок/предупреждений).
2. **Ответ weekly** (и при проверке, и при загрузке) — по каждой книге: имя файла, группа, неделя, даты недели, число пар, ошибки и предупреждения (ячейка, текст, причина); итог: файлов, групп (новых), пар, сколько временных изменений будет/было удалено, ошибок, `applied: bool`. Для `dry_run` — **тот же** `import_weekly` в транзакции, которая затем откатывается (`rollback`), чтобы проверка показывала ровно то, что сделает загрузка, включая счётчик удаляемых изменений.
3. **Ответ semester**: при `dry_run` — только разбор (`parse_workbook`): группы с числом пар, предупреждения парсера; плюс сколько сейчас пар у этих групп в базе (будут заменены) и сколько у них временных изменений, привязанных к парам (удалятся). При загрузке — `import_workbook` (он сам коммитит) и итог из `ImportReport`.
4. **Ошибки:** нет активного семестра → 409 с русским текстом; неверное расширение / пустой список / файл больше **20 МБ** (каждый) или суммарно больше **50 МБ** → 400/413 с русским текстом; книга, которую не удалось прочитать, — ошибка этой книги в отчёте, а не 500. При ошибках и `skip_errors=false` загрузка ничего не пишет и возвращает отчёт с `applied=false` (HTTP 200 — это результат проверки, не сбой).
5. **Файлы** сохраняются во временную папку (`TemporaryDirectory`) и удаляются после ответа; имя на диске — порядковое (`0.xlsx`), **исходное имя пользователя на путь не влияет** (защита от `../`). Исходное имя (только базовое, без пути) передаётся парсеру как запасной источник названия группы (решение 2 задачи 001) — для этого `import_weekly` может принимать пары (путь, отображаемое имя); CLI работает как раньше.
6. **Кто загрузил:** `schedule_imports.uploaded_by` = логин админа (как `created_by` у изменений) — для weekly и semester. CLI оставляет `None`.
7. **Новая зависимость** `python-multipart` (нужна FastAPI для `UploadFile`/`Form`) — в `requirements.txt` с точной версией.
8. **Фронтенд — раздел «Загрузка»** в табах админки (рядом с «Расписание», «Сообщения», …):
   - переключатель «Магистры — по неделям» / «Бакалавры — семестр»;
   - выбор файлов (`<input type="file" multiple accept=".xlsx,.zip">` для магистров, один `.xlsx` для бакалавров) + перетаскивание на область; список выбранных с размером и кнопкой убрать;
   - **«Проверить»** → таблица по книгам: группа, неделя (даты), пар, статус (✓ / предупреждения / ошибка с текстом и ячейкой) и итог; для бакалавров — группы и число пар, сколько пар и изменений будет заменено;
   - **«Загрузить»** активна только после успешной проверки тех же файлов; если есть ошибки — неактивна, и рядом флажок «Пропустить файлы с ошибками» (weekly). Для бакалавров перед загрузкой — подтверждение: «Будут заменены пары групп: … (N пар, M временных изменений удалится)».
   - после загрузки — итог и сброс кэша TanStack Query расписания/групп (`invalidateQueries`), чтобы новые группы и пары сразу появились;
   - внизу — «Последние загрузки» (`GET /admin/imports`).
   - Разметку можно взять из `pages/admin/DemoAdminScreens.tsx` (экран `excel`) как ориентир; сам файл не подключать и не удалять. Стили — по образцу соседних админских экранов.

## Тесты (до кода)

- `weekly` dry_run: книги (генератор из `tests/test_weekly_import.py`) → отчёт с группой/неделей/парами, в базе ничего не появилось; повтор без dry_run → пары в базе, `schedule_imports.uploaded_by = admin`.
- `weekly`: одна книга битая → `applied=false`, база пуста; с `skip_errors=true` — корректная записана.
- `weekly`: zip из нескольких книг; файл `../../evil.xlsx` в имени — ничего не пишется вне временной папки, имя в отчёте — базовое.
- `weekly` dry_run считает изменения (override), которые удалятся при перезагрузке недели.
- Ограничения: не-`.xlsx/.zip` → 400; слишком большой файл → 413 (лимит вынеси в настройку/константу, в тесте подмени на маленький); без токена → 401; студентский токен → 401/403.
- `semester` dry_run на маленькой книге — если собрать книгу бакалавров в тесте слишком сложно, тест с реальным Excel пропускается без файла (как остальные сквозные), а ошибочные случаи (не `.xlsx`, битый файл → отчёт с ошибкой, без 500) — тестируются на сгенерированных файлах.
- `GET /admin/imports` возвращает последние записи в порядке убывания даты.
- Все прежние тесты зелёные; `npm run build` проходит.
