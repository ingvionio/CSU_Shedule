# Заказ справок через обращения

Студент заказывает справку из «Обращений» или профиля. ФИО и группа подставляются из профиля Moodle. Студент указывает, для чего нужна справка и сколько экземпляров подготовить. Дополнительная информация необязательна. Заказ появляется в истории студента с пометкой «Справка». Методист работает с заказами в отдельной папке и использует существующие статусы и ответы.

## Вопросы к архитектору

Открытых вопросов нет.

## Отчёт

- Ветка `feature/certificate-requests` создана от `origin/master` (`91fc227`) после `git fetch origin`. На тот момент `security/full-audit` указывала на тот же коммит. Незакоммиченные изменения аудита остались в рабочей копии. Слияния, коммита, push и выкладки не было.
- `backend/app/api/v1/feedback.py`, `backend/app/schemas/feedback.py`, `backend/app/services/feedback.py` и модели обращений поддерживают тип `certificate` в существующем `POST /api/v1/feedback`. Сервер отклоняет переданные клиентом данные автора, группы и адресата. Студент с действующей Moodle-сессией видит только свои заказы. Применяются общие квоты по аккаунту и IP и проверка дублей под той же блокировкой. При отсутствии группы в профиле заказ отклоняется.
- Справки закреплены за методистом. Заказы и ответы обрабатываются внутри приложения с действующей проверкой прав админа. Персональные данные заказа остаются в приложении. Почтовая рассылка обычных обращений использует прежние настройки.
- `frontend/src/App.tsx`, `frontend/src/navigation.ts` и страницы обращений добавляют два входа в форму, подтверждение, историю со статусом и папку «Справки». Обновлены студенческий FAQ и подсказки администратора.
- Alembic `fa39c812bf51` (`backend/migrations/versions/fa39c812bf51_certificate_requests.py`) расширяет ограничение `kind` после `f9a9b1c2d350`. Старые строки при обновлении сохраняются. При откате заказы переходят в папку методиста с сохранением текста, автора, статуса и ответов.
- Новых зависимостей нет.

### Результаты проверок

- 58 серверных тестов обращений, авторизации, квот, отзыва сессий и миграций прошли. Регрессионные тесты покрывают данные профиля, подмену личности, доступ владельца и методиста, общие квоты, параллельную отправку и обычные обращения.
- На локальном PostgreSQL 16 проверены обновление, откат и повторное обновление с существующим обращением и ответом. При шести одинаковых параллельных запросах к двум процессам API создан один заказ. Остальные получили `429` с `Retry-After`.
- `npm test` — 61 тест прошёл. `npm run build` — успешно. В Chrome с тестовым Moodle проверены оба входа в форму, подтверждение, история, ответ и закрытие заказа. Форма и админка проверены на ширинах 320, 390, 768 и 1440 px. Проверка на физических Android и iOS не проводилась.
- По умолчанию часть серверных тестов начинает проверять отзыв админской сессии до создания общей схемы SQLite. Полный набор запущен с `tests/test_feedback.py` первым, чтобы схема создалась штатной фикстурой. Прошло 513 тестов. `test_список_без_n_plus_one` в `tests/test_messages.py` ожидает три SQL-запроса. Аудит добавил четвёртый для проверки отзыва админской сессии. Ещё 35 тестов пропущены из-за отсутствия рабочего Excel расписания.

### Как проверить

Из `backend/` запустить `.venv\Scripts\python -m pytest -q tests/test_feedback.py tests/test_feedback_author.py tests/test_api_protections.py tests/test_admin_session_revocation.py tests/test_async_merge.py`. Из `frontend/` запустить `npm test` и `npm run build`. Миграция применяется командой `.venv\Scripts\python -m alembic upgrade head` к тестовой базе.

В приложении открыть «Заказать справку» из профиля и «Обращений», отправить заказ и открыть «Мои обращения». В кабинете методиста открыть «Обращения» → «Справки», ответить и поставить статус «Закрыто». Статус и ответ доступны в истории автора.

### Обязательные поля заказа

- Форма и API требуют непустую цель и целое количество экземпляров от одного. Верхняя граница количества соответствует диапазону `INTEGER` в PostgreSQL. Дополнительный комментарий остаётся отдельным полем.
- Цель и количество сохраняются в заказе и видны в истории студента и карточке методиста. Проверка дублей учитывает оба поля. Квоты на аккаунт и IP общие для всех обращений.
- Миграция `fb43e912ac62` добавляет два поля после `fa39c812bf51`. Существующие заявки сохраняются. Если у старого заказа нет цели и количества, карточка методиста показывает прочерки. При откате удаляются два новых поля. Новых зависимостей нет.
- Прошли 59 серверных и 61 фронтенд-тест, а также `npm run build`. На PostgreSQL 16 проверены миграция с существующим заказом, откат и параллельная отправка. В Chrome проверены обязательность обоих полей, отказ для дробного количества, отправка и просмотр данных у методиста.

### Отметки о новых ответах и статусах

- Счётчик у «Обращений» в нижней навигации и на вкладке «Мои обращения» показывает число карточек с непрочитанными обновлениями. Карточка выделяется и показывает «Новый ответ» или «Статус обновлён» рядом с текущим статусом. Действие «Отметить прочитанным» снимает выделение. Следующее изменение снова выделяет карточку.
- `frontend/src/api/queries.ts` обновляет историю через существующий API каждые 30 секунд в открытом приложении. `frontend/src/pages/feedback/updates.ts` запоминает отметки прочтения отдельно для каждого профиля в текущем браузере. Отметки на других устройствах ведутся независимо. Изменений API, миграций и зависимостей нет.
- `npm test` — 63 теста прошли. `npm run build` — успешно. Тесты проверяют счётчики, подсветку, сохранение прочтения и повторное появление отметки при ответе или смене статуса.
- В Chrome проверены автоматическое появление счётчика после смены статуса, выделение нового ответа на закрытом заказе и сохранение прочтения после перезагрузки.
