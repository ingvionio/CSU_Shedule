# 011 — Уведомления об изменении расписания и «расписание не загружено» у магистров

Ветка `feature/session-schedule`. Начинать после приёмки задачи 010 (нужны её
события сессии). Опирается на outbox и worker задачи 007 и рассылку
(`app/services/messages.py`).

## Решения (Лёша, 21.11.2026)

1. Изменение расписания → **сообщение во вкладке «Сообщения» + push**
   (обычный путь рассылки: инбокс, push по устройствам, статистика).
2. Поводы: разовые изменения пар (и их откат), правки сессии и пересдач в
   админке, новая загрузка файла (семестр, понедельный, сессия/пересдачи).
3. **Собирать за 2 минуты**: изменения одной группы копятся; когда 2 минуты
   новых нет — уходит одно сообщение. Изменение и его откат внутри окна
   взаимно гасятся — ничего не приходит.
4. У **магистров** (понедельное расписание) неделя без загруженных пар
   показывает «Методист ещё не загрузил расписание, оно появится позже»
   вместо «Занятий нет».

## Часть А. Уведомления

### А1. Очередь изменений (миграция)

`schedule_changes`:

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | int PK | |
| `group_id` | FK `groups` CASCADE, index | кому |
| `source` | varchar(16) CHECK `override`/`exam`/`import` | |
| `ref_id` | int NULL | id изменения (`lesson_overrides.id`, `exam_events.id`); для гашения пар |
| `action` | varchar(16) CHECK `created`/`changed`/`removed`/`uploaded` | |
| `day` | date NULL | дата, которой касается изменение |
| `text` | varchar(300) | готовая строка для сообщения (см. А3) |
| `created_at` | timestamptz | |
| `message_id` | FK `messages` SET NULL, NULL | каким сообщением ушло |
| `processed_at` | timestamptz NULL | обработано (ушло или погашено) |

Индекс по необработанным `(processed_at, group_id, created_at)`.

### А2. Запись — в той же транзакции, что изменение

Одна функция `app/services/schedule_changes.py::record(db, …)` без commit.

- `overrides.create_overrides` — по строке на каждую группу каждого
  созданного изменения (поток → у каждой группы своя строка), `created`;
  `delete_override` — `removed` с тем же `ref_id`.
- События сессии (010): создание `created`, правка/отмена/возврат `changed`,
  удаление `removed`; по строке на каждую группу события.
- Применение загрузки (семестр, понедельная, сессия/пересдачи) — одна строка
  `uploaded` на каждую затронутую группу; проверка без применения ничего не
  пишет.
- Изменения с `day` **раньше сегодняшнего** не записываются.

### А3. Тексты

Строки собираются при записи, по-русски, коротко, с датой «12 ноября (ср)»:

- отмена: «12 ноября (ср), 2 пара — Математический анализ: отменена»;
- перенос: «… перенесена на 14 ноября (пт), 4 пара»;
- замена: «… изменения: ауд. 214 → 305, преподаватель …» (только изменённые поля);
- доп. пара: «13 ноября (чт), 5 пара — Программирование: дополнительная пара»;
- откат: «… изменение отменено, пара по обычному расписанию»;
- сессия: «Пересдача 5 октября (пн), 15:15 — Информатика: перенесена с 28 сентября», «… аудитория 132 → 132а», «… отменена», «… добавлена»;
- загрузка: «Расписание обновлено», для понедельной — «Загружено расписание на неделю 12 (16–22 ноября)», для сессии — «Опубликовано расписание сессии» / «… пересдач».

### А4. Сборка сообщений в worker

Новый шаг `process_schedule_changes(db, now)` в цикле worker'а (007):

- группы, у которых есть необработанные строки и **самая новая старше
  2 минут** (`SCHEDULE_CHANGE_DELAY_SECONDS`, по умолчанию 120);
- гашение: `created` и `removed` с одним `source`+`ref_id` в одной пачке
  взаимно уничтожаются; если после этого строк нет — помечаются
  обработанными без сообщения;
- иначе одно сообщение группе через `messages.create_message` (как рассылка
  методиста): заголовок «Изменение расписания» (для одной строки
  `uploaded` — её текст), текст — строки по дате, не больше 10 + «и ещё N»;
  важность `normal`, адресат — группа, `created_by = "system"`;
- захват строк — как в 007 (`FOR UPDATE SKIP LOCKED`), без двойной отправки
  при двух worker'ах; строки помечаются в той же транзакции, что создаётся
  сообщение.

### А5. Админка

В списке рассылок автоматические сообщения помечены «автоматически» и
фильтруются переключателем «Показать автоматические» (по умолчанию скрыты,
чтобы не забивать список). Статистика прочтения/доставки — как у обычных.

## Часть Б. «Расписание не загружено» у магистров

- Неделя группы магистратуры (`groups.level == "master"`), номер которой
  **не меньше текущей**, и в которой у группы нет ни одной пары (постоянных
  и добавленных) → в ответе недели `week.schedule_pending = true`; иначе
  `false`. Считает бэкенд (правило 1).
- `GET /groups/{id}/day` (если есть) — то же для недели этого дня.
- Фронт: при `schedule_pending` вместо дней с «Занятий нет» — одна плашка
  «Методист ещё не загрузил расписание, оно появится позже» (и в «На день»,
  и в «На неделю»).
- Контракт `03-schedule-json.md` дописывает архитектор.

## Тесты

- запись в одной транзакции (откат изменения — строк нет); прошлые даты не
  пишутся; поток → строка на каждую группу;
- тексты для каждого вида изменения;
- worker: ждёт 2 минуты с последнего изменения (подмена `now`); одно
  сообщение на группу; гашение пары создано/удалено; при двух вызовах подряд
  — без повтора; push ставится в outbox через обычный путь;
- загрузка применённая — строка `uploaded`; проверка без применения — нет;
- магистры: прошлая пустая неделя — `false`, текущая/будущая пустая — `true`,
  неделя с парами — `false`; бакалавры — всегда `false`;
- `npm run build`.

## Вне задачи

- переход по push сразу на день расписания (пока открывается сообщение);
- настройка «не присылать уведомления об изменениях» у студента.
