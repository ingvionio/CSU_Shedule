# Что сделано на текущий момент

Первый рабочий срез: **статичное расписание без изменений и без админки**.
Расписание из Excel лежит в базе, API отдаёт его на неделю, студент выбирает
группу и видит свои пары.

## Как это работает

```
Excel (рабочий вариант ИИТ)
   │  python -m app.cli import-excel   (разовая команда, вручную)
   ▼
PostgreSQL  ──►  FastAPI  ──HTTP/JSON──►  React (Vite)
  в Docker       в Docker                 локально, npm run dev
```

Бэкенд полностью отвечает за корректность: сам отбирает пары по чётности
недели и сроку действия, сортирует по времени и отдаёт готовый JSON.
Фронт ничего не вычисляет — только рисует.

## Где что запускается

| Часть | Где живёт | Как поднять |
|---|---|---|
| PostgreSQL 16 | **Docker**, том `csu_shedule_postgres_data` | `docker compose up -d` |
| FastAPI | **Docker**, порт 8000 | то же |
| React | **локально, не в Docker** | `cd frontend && npm run dev` |

**Важно:** фронтенд в Docker не заведён намеренно — для разработки удобнее
Vite с горячей перезагрузкой. В `docker-compose.yml` его нет, образа для него
нет. Запускается только командой `npm run dev` на машине разработчика.

Порты:

* `localhost:8000` — API (`/docs` — интерактивная документация);
* `localhost:5173` — фронтенд;
* `localhost:5433` — Postgres наружу. **Не 5432** — чтобы не конфликтовать
  с локально установленным Postgres. Внутри docker-сети бэкенд ходит на 5432.

Бэкенд в контейнере запущен **без `--reload`**, хотя `./backend` примонтирован.
После правок кода нужен `docker compose restart backend`.

## Запуск с нуля

```bash
# 1. База и API
docker compose up -d --build
docker compose exec backend python -m alembic upgrade head
docker compose exec backend python -m app.cli seed-semester

# 2. Залить расписание (файл лежит вне смонтированной папки, поэтому копируем)
docker compose cp "./Расписание_ИИТ_1_сем_26_27_уч_г_РАБОЧИЙ_ВАРИАНТ.xlsx" backend:/tmp/schedule.xlsx
docker compose exec backend python -m app.cli import-excel /tmp/schedule.xlsx
docker compose exec backend python -m app.cli stats     # проверить, что залилось

# 3. Фронтенд
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Данные переживают `docker compose down` — они в томе. Повторный импорт
заменяет пары семестра, дубликатов не создаёт.

## Что умеет парсер

Раскладка листа определяется автоматически, поэтому работает и на листе
`ПрИ 201,202,203`, где всё сдвинуто на столбец.

| В файле | Как разбирается |
|---|---|
| `1Н.` / `2Н.` / без префикса | нечётная / чётная / каждую неделю |
| `(ЛЕК.)`, `(ПР.)`, `(ЛАБ.)`, `(ЛЕК.+ПР.)` | формат пары |
| `(9-15 НЕД.)` | срок действия пары |
| `с 19:00` в начале ячейки | пара вне сетки: своё время, `slot = null` |
| `АУД. 132Б`, `ФОК` | аудитория; без них — пусто (онлайн-курс) |
| название на двух строках | склеивается в одно |
| два преподавателя через запятую | сохраняются оба |
| `ДЕНЬ САМОСТОЯТЕЛЬНЫХ ЗАНЯТИЙ`, подписи, сноски | отбрасывается |

Названия групп сохраняются **как в файле**: `ИТ1-ПрИб-11`, `ПИ 201`, `БИ 301`.

## Принятые решения

* **Подгруппы не фильтруются.** В Excel группа занимает два столбца, и пара
  может стоять только для одной подгруппы. По договорённости это пока
  игнорируется: API отдаёт все пары, фронт помечает их «1 подгруппа».
  При этом поле `subgroup` **сохраняется в базе** — когда станет понятно,
  как устроено нововведение первого курса, фильтр добавится без перепарсинга.
* **`/time-slots` сделан публичным**, хотя в архитектуре он под админкой —
  без него фронт не построит сетку недели.
* **Excel не коммитится** (так же, как задано в `backend/.gitignore`).
  Сквозные тесты берут файл из корня репозитория и пропускаются, если его нет.

## Чего ещё нет

* временные изменения (`lesson_overrides`): отмена, перенос, замена, доп. пара.
  У всех пар в ответе `status: "regular"`, `change: null`. **Вёрстка фронта
  статусы уже поддерживает** — подключится без переделки UI;
* админка и загрузка Excel через API — пока только команда в консоли;
* авторизация, вход через Moodle;
* PWA: манифест и service worker (офлайн сейчас держится на `localStorage`);
* React Router — экраны переключаются состоянием;
* фронтенд в Docker.
