# Что сделано на текущий момент

- **Расписание.** Бакалавры получают расписание из семестрового Excel,
  магистры 1 курса — из файлов на группу и неделю. У онлайн-пар может быть
  ссылка «Подключиться». Разные аудитории по чётности поддерживаются для
  записей вида `АУД. 425/201` ([задача 006](tasks/006-room-week-parity.md)).
- **Вход.** Студенческий интерфейс использует Moodle ИИТ с автоматическим
  определением группы. Бэкенд связывает устройства в один профиль и хранит
  пароль Moodle в зашифрованном виде для продления сессии. Запросы
  опубликованного расписания публичны, личные разделы требуют студенческий JWT.
  Резервный API регистрации по ФИО и группе сохранён.
- **Админка.** Методист проверяет и загружает семестровые и понедельные файлы,
  смотрит историю загрузок, вносит и откатывает разовые изменения для группы
  или потока. Импорт и разовые изменения вступают в силу сразу после записи.
- **Студенческие сервисы.** Есть групповая домашка, личные заметки к парам,
  карта ЧелГУ и справка. Обращения доступны в приложении и могут дублироваться
  на почту при настроенном SMTP. Методист рассылает сообщения, видит
  подтверждения ознакомления, доставку push по устройствам и отправляет
  напоминания. Push: браузер и iPhone (PWA) — Web Push, нужны VAPID и HTTPS;
  Android-приложение — FCM, нужны `google-services.json` и ключ сервисного
  аккаунта Firebase. Отправляет отдельный процесс `worker` с повторами.
- **Доставка.** PWA и Android-проект Capacitor используют один React-фронтенд
  и один API. Готовый APK в репозитории не хранится. [Сборка APK](frontend/README.md#android-apk).

## Как это работает

```
Excel (рабочий вариант ИИТ)
   │  админка «Загрузка» или CLI
   ▼
PostgreSQL  ──►  FastAPI  ──HTTP/JSON──►  React (Vite)
  в Docker       в Docker                 локально, npm run dev
```

Бэкенд полностью отвечает за корректность: сам отбирает пары по чётности
недели и сроку действия, применяет временные изменения, сортирует по времени
и отдаёт готовый JSON.
Фронт ничего не вычисляет — только рисует.

## Где что запускается

| Часть | Где живёт | Как поднять |
|---|---|---|
| PostgreSQL 16 | **Docker**, том `csu_shedule_postgres_data` | `docker compose up -d` |
| FastAPI | **Docker**, порт 8000 | то же |
| React | **локально, не в Docker** | `cd frontend && npm run dev` |

**Важно:** фронтенд в Docker не заведён намеренно — для разработки удобнее
Vite с горячей перезагрузкой. В `docker-compose.yml` его нет, образа для него
нет. Запускается только командой `npm run dev` на машине разработчика.

Порты:

* `localhost:8000` — API (`/docs` — интерактивная документация);
* `localhost:5173` — фронтенд;
* порт API наружу меняется переменной `BACKEND_PORT` (например,
  `BACKEND_PORT=8001 docker compose up -d`), если 8000 занят; тогда фронт
  запускать с `VITE_API_URL=http://localhost:8001`;
* `localhost:5433` — Postgres наружу. **Не 5432** — чтобы не конфликтовать
  с локально установленным Postgres. Внутри docker-сети бэкенд ходит на 5432.

Бэкенд в контейнере запущен **без `--reload`**, хотя `./backend` примонтирован.
После правок кода нужен `docker compose restart backend`.

## Запуск с нуля

```bash
# 1. База и API
docker compose up -d --build
docker compose exec backend python -m alembic upgrade head   # и после каждого pull с новыми миграциями
docker compose exec backend python -m app.cli seed-semester

# 2. Залить расписание (файл лежит вне смонтированной папки, поэтому копируем)
docker compose cp "./Расписание_ИИТ_1_сем_26_27_уч_г_РАБОЧИЙ_ВАРИАНТ.xlsx" backend:/tmp/schedule.xlsx
docker compose exec backend python -m app.cli import-excel /tmp/schedule.xlsx
docker compose exec backend python -m app.cli stats     # проверить, что залилось

# 3. Фронтенд
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Данные переживают `docker compose down` — они в томе. Повторный импорт
заменяет пары семестра, дубликатов не создаёт.

## Данные локального стенда

Состав групп и занятий зависит от загруженных файлов. Состояние подключённой
базы показывает `python -m app.cli stats`, предупреждения об импорте
доступны в истории загрузок.

Семестр: `1 семестр 2026/27`, 18 недель, неделя 1 начинается в понедельник
31 августа 2026 (от даты начала 1 сентября), первая неделя нечётная.
Меняется флагами `seed-semester --start ... --weeks ... --parity ...`.

Сетка звонков: 08:00, 09:40, 11:20, 13:15, 15:00, 16:40, 18:20, 19:55
(пары по 1 ч 30 мин). Лежит в таблице `time_slots`.

## Что умеет парсер

Раскладка листа определяется автоматически, поэтому работает и на листе
`ПрИ 201,202,203`, где всё сдвинуто на столбец.

| В файле | Как разбирается |
|---|---|
| `1Н.` / `2Н.` / без префикса | нечётная / чётная / каждую неделю |
| `(ЛЕК.)`, `(ПР.)`, `(ЛАБ.)`, `(ЛЕК.+ПР.)` | формат пары |
| `(9-15 НЕД.)` | срок действия пары |
| `с 19:00` в начале ячейки | пара вне сетки: своё время, `slot = null` |
| `АУД. 132Б`, `ФОК` | аудитория; без них — пусто (онлайн-курс) |
| `АУД. 425/201` | первая аудитория по нечётным неделям, вторая по чётным |
| название на двух строках | склеивается в одно |
| два преподавателя через запятую | сохраняются оба |
| `ДЕНЬ САМОСТОЯТЕЛЬНЫХ ЗАНЯТИЙ`, подписи, сноски | отбрасывается |

Названия групп сохраняются **как в файле**: `ИТ1-ПрИб-11`, `ПИ 201`, `БИ 301`.

## Принятые решения

* **Подгруппы не фильтруются.** В Excel группа занимает два столбца, и пара
  может стоять только для одной подгруппы. По договорённости это пока
  игнорируется: API отдаёт все пары, фронт помечает их «1 подгруппа».
  При этом поле `subgroup` **сохраняется в базе** — когда станет понятно,
  как устроено нововведение первого курса, фильтр добавится без перепарсинга.
* **`/time-slots` публичный**: фронтенд использует его для сетки недели.
* **Изменения хранятся отдельно, на фронт уходит один JSON.** Постоянные
  пары не перезаписываются; `lesson_overrides` применяются при сборке недели.
  Отдельного JSON с изменениями нет — фронт ничего не сводит сам.
* **Изменения сразу публикуются.** Черновика и кнопки «Опубликовать» нет;
  ошибку админ исправляет откатом изменения. Поле `status` в таблице оставлено
  под черновики.
* **Вход админа — один логин/пароль из `.env`** (`ADMIN_LOGIN`,
  `ADMIN_PASSWORD`, `JWT_SECRET`). Админ получает JWT. Студенческие профили
  хранятся в таблице `users`.
* **Пересечения по времени запрещены** (409). Отменённые и перенесённые
  пары не мешают, пары разных подгрупп могут стоять одновременно.
* **Режим «Поток» в админке (12.11.2026).** В списке — группы того же курса
  и уровня (бакалавры / магистры, `groups.level` вычисляется из направления).
  Сетка показывает только пары, общие для всех отмеченных групп (тот же день,
  время и предмет исходной пары; доп. пары — одно действие на поток); если у
  групп общая пара отличается — пометка «У групп по-разному». Задача —
  `tasks/004-stream-view.md`.
* **Поток** = одно действие на несколько групп с общим `batch_id`. Пара у
  остальных групп ищется по дню, времени и предмету; неизменённые поля
  (аудитория, преподаватель) у каждой группы остаются своими.
* **Повторный импорт Excel** удаляет изменения, привязанные к старым
  парам (отмена, перенос, замена); доп. пары остаются. Заменяются только
  пары групп, которые есть в файле, — магистры при импорте бакалавров не стираются.
* **Магистры (11.11.2026).** Каждая пара из понедельного файла — обычная
  постоянная пара со сроком в одну неделю (`week_from = week_to = N`, каждую
  неделю). Сноски со звёздочками («через неделю по средам») не используются:
  файл и есть расписание конкретной недели; звёздочки убираются из названия.
  Группа — из шапки файла, при неоднозначности берётся вариант с трёхзначным
  номером (`МИТ 101`, а не `МИТ-11` из имени файла). Направление (поток) —
  своё: `МИТ`, `МПрИ`, `МПИ`, `МБИ`, с бакалаврскими не смешивается.
  Курс — 1, поэтому рассылка «1 курсу» сейчас дойдёт и до магистров (открытый вопрос).
* **Домашка при перезагрузке расписания (11.11.2026).** Пары при импорте
  пересоздаются, поэтому групповая домашка перепривязывается к новой паре той же
  группы в тот же день: сначала по времени и предмету, иначе — к единственной паре
  этого предмета в этот день; неоднозначно или пары нет — задание остаётся без пары
  (видно в «Заданиях на неделю»). Счётчики «перепривязано / отвязано» — в отчёте
  проверки, загрузки и в CLI. Задача — `tasks/003-homework-rebind-on-reimport.md`.
* **Суббота у магистров [предварительно].** Номера субботних пар в файлах
  ненадёжны, поэтому пара «с 13:10» встаёт вне сетки (13:10–14:40), а
  следующая — в 5-ю пару (15:00–16:30). Нужно подтвердить у методиста.
* **Обращения без входа студента.** Автор узнаётся по случайному токену
  устройства, бэкенд хранит его хеш. Имя и контакт необязательны.
  Подготовлено к Moodle: обращения привяжутся к пользователю по токену.
* **Письма через очередь** `email_outbox`: сбой SMTP не теряет обращение.
  Без `SMTP_USER` письма только пишутся в лог.
* **Доставка уведомлений — outbox в Postgres без брокера (19.11.2026).**
  Push и письма записываются в `push_deliveries` / `email_outbox` в той же
  транзакции, что сообщение или обращение; отдельный процесс `worker`
  отправляет их с повторами (`SKIP LOCKED`, нарастающая задержка). Брокер
  (NATS и т. п.) для монолита с такой нагрузкой не нужен: лишний сервис и
  вторая очередь поверх outbox. Задача — `tasks/007-notification-outbox.md`.
* **Push по платформам (19.11.2026).** Android-приложение — FCM; телефоны
  Huawei/Honor без сервисов Google — Huawei Push Kit (HMS), делается после
  FCM отдельной задачей. iPhone — только PWA (Web Push, iOS 16.4+, приложение добавлено на
  экран «Домой»); нативной iOS-сборки и APNs не будет. Все отправители —
  в worker из задачи 007.
* **Без Cloudflare (19.11.2026).** Прод — iit-app.ru, nginx на сервере с
  белым IP, фронт и `/api` на одном домене, HTTPS на nginx. Прокси
  Cloudflare не используем: в России его замедляют, а нужного проекту
  (HTTPS, нагрузка) он не добавляет. Push от него не зависит.
* **Прод без Docker (20.11.2026, со слов администратора).** Debian 13,
  systemd-сервисы `csu-backend` и `csu-worker` из venv релиза
  (`~/csu_schedule/releases/current`), PostgreSQL 17 на сервере, фронт
  собирается у разработчика и кладётся в `/var/www/csu_schedule`. Сайт открыт
  на iit-app.ru и illusoryorb.ru, поэтому собирается без `VITE_API_URL`.
  Порядок выкладки — `DEPLOY.md`.
* **Подпись APK.** Опубликованные версии (до 1.1.1, versionCode 3) подписаны
  ключом `csu-release-key.jks` из ветки `feature/apk-build`; обновления —
  только им, иначе приложение не встанет поверх установленного.
* **Excel не коммитится** (так же, как задано в `backend/.gitignore`).
  Сквозные тесты берут файл из корня репозитория и пропускаются, если его нет.
