# Обращения студентов

Раздел «Вопросы» в приложении: студент пишет методисту, в деканат или
разработчикам. Обращение попадает в папку админки, при необходимости
дублируется на почту адресата, а ответ студент видит в приложении.

## Как это работает

```
Студент ─ POST /feedback ─► feedback_messages ─► папка в админке
                               │
                               └─► email_outbox ─► SMTP Яндекса ─► почта адресата
                                                   (Reply-To: почта студента)
Админ ─ ответ ─► feedback_replies ─► «Мои обращения» у студента
                                 └─► email_outbox ─► почта студента (если оставил)
```

* **Папки** = кому адресовано: Разработчики, Методист, Деканат и
  **Не распределено** — студент выбрал «Не знаю, кому». Такое обращение
  админ переносит в нужную папку, и письмо уходит новому адресату.
* **Адресаты** (`feedback_recipients`) настраиваются в админке:
  «Обращения» → «Адресаты и почта». Пустой список email — только админка.
  Адресаты заводятся сами при первом обращении к разделу.
* **Статусы**: новое → в работе → есть ответ → закрыто. Ответ сам ставит
  «есть ответ».
* **Заметка** к обращению видна только в админке.

## Кто пишет

Входа у студента пока нет, поэтому:

* обращение может быть **анонимным**: имя и контакт необязательны;
* приложение создаёт случайный **токен устройства** (`localStorage`,
  заголовок `X-Feedback-Token`). Бэкенд хранит только HMAC-хеш токена. По
  нему студент видит «Мои обращения» и ответы. Новое устройство или
  очищенный браузер — обращения не видны;
* если студент оставил имя или контакт, форма просит согласие на обработку
  данных.

**Когда появится вход через Moodle:** в `feedback_messages` добавится
`author_user_id`. При первом входе фронт передаст токен устройства, и бэкенд
привяжет обращения с этим хешем к пользователю. «Мои обращения» будут
искаться по пользователю, имя и группа подставятся из профиля. Токен
устройства останется для тех, кто пишет без входа.

## Почта

* SMTP Яндекса, настройки `SMTP_USER` / `SMTP_PASSWORD` (пароль приложения),
  как подключить — в [README.md](README.md#почта-для-обращений-яндекс).
* Письмо сначала записывается в `email_outbox` вместе с обращением и
  отправляется в фоне после ответа API. Недоступный SMTP не теряет
  обращение: письмо остаётся `pending`, ошибка в `last_error`, досылка —
  `python -m app.cli send-emails` (после 5 неудачных попыток — `failed`).
* Без `SMTP_USER` письма не уходят: текст пишется в лог, статус `skipped`.
* Письмо адресату содержит `Reply-To` студента, если тот оставил email:
  методист может ответить прямо из почты. Но тогда ответа не будет
  в приложении — для этого отвечать в админке.

## Защита от спама

* не больше 5 обращений в час с устройства и 40 с IP (общий Wi-Fi вуза),
  `FEEDBACK_RATE_LIMIT_PER_HOUR`, `FEEDBACK_IP_RATE_LIMIT_PER_HOUR`;
* скрытое поле-ловушка `website`: заполнено — обращение отклоняется;
* текст 5–4000 символов. Капчи нет; при спаме добавить.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/feedback` | отправить обращение (заголовок `X-Feedback-Token` необязателен) |
| GET | `/api/v1/feedback/mine` | обращения устройства с ответами |
| GET | `/api/v1/admin/feedback?kind=&status=` | обращения в папке |
| GET | `/api/v1/admin/feedback/folders` | папки: всего и новых |
| PATCH | `/api/v1/admin/feedback/{id}` | статус, заметка, перенос в папку (`kind`) |
| POST | `/api/v1/admin/feedback/{id}/replies` | ответ студенту |
| GET | `/api/v1/admin/feedback/recipients` | адресаты |
| PATCH | `/api/v1/admin/feedback/recipients/{id}` | email, название, вкл/выкл |

## Таблицы

| Таблица | Что хранит |
|---|---|
| `feedback_recipients` | адресат: `kind` (папка), название, `emails`, `is_active`, `sort_order` |
| `feedback_messages` | обращение: папка, адресат, текст, группа, имя, контакт, хеши токена и IP, статус, заметка |
| `feedback_replies` | переписка: автор (`staff` / `student`), текст. Отдельная таблица, а не поле — под уточнения студента и ответы ссылкой на FAQ |
| `email_outbox` | очередь писем: кому, Reply-To, тема, текст, статус, попытки, ошибка |

## Задел на будущее

### Деканат из нескольких человек

Адресатов одного вида может быть несколько. Сейчас обращение уходит первому
активному по `sort_order`. Когда деканат разделится, добавятся новые записи
`kind = deanery` и правило выбора — по теме (см. ниже) или по курсу.

### Одинаковые вопросы (методист отвечает 10 раз на одно и то же)

1. **База ответов (FAQ).** Таблица `faq_entries` (вопрос, ответ, папка,
   опубликован). В карточке обращения кнопка «Сделать статьёй»: вопрос
   и ответ переписываются без личных данных и публикуются.
2. **Подсказки до отправки.** Пока студент пишет вопрос, форма ищет похожие
   статьи (полнотекстовый поиск Postgres с русским словарём или `pg_trgm`)
   и показывает «Возможно, ответ уже есть». Большая часть повторов не дойдёт
   до методиста.
3. **Ответ пачкой.** В админке отметить несколько похожих обращений
   и ответить один раз — ответ разойдётся всем (или ссылкой на статью,
   `feedback_replies.faq_entry_id`).
4. Позже — группировка похожих новых обращений в админке тем же поиском.

### Студент не знает, кому писать

1. **Уже есть:** «Не знаю, кому» → папка «Не распределено» → админ переносит.
   Под выбором адресата — подсказка, кто чем занимается
   (`frontend/src/pages/feedback/labels.ts`; формулировки сверить
   с деканатом).
2. **Темы вместо адресатов.** Справочник `feedback_topics` («Военный учёт»,
   «Стипендия», «Справки», «Расписание», «Практика»…) с адресатом у каждой
   темы. Студент выбирает тему, адресат определяется сам; «Другое» —
   в «Не распределено». Темы и их адресатов правит админ, тогда и деканат
   из нескольких человек раскладывается по темам.
3. Поиск по FAQ из пункта выше тоже отвечает на вопрос «кому».

### Вопросы другим студентам

Отложено: это публичный форум, ему нужны модерация и вход студента, иначе
анонимные сообщения не контролировать. Вернуться после Moodle.

### Вход методиста и деканата

Сейчас они получают письма, а в админку заходит один админ. С появлением
пользователей и ролей — роль с доступом только к своей папке.
