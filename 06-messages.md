# Сообщения студентам: рассылка, прочтение, push

Методист отправляет сообщение всем, курсу, потоку, группам или конкретным
студентам. Студент видит его в разделе «Сообщения» и получает
push-уведомление, у важных нажимает «Ознакомлен». Методист видит, кто прочитал
и кто подтвердил, и может напомнить остальным.

Основание — ТЗ «Система информирования студентов» v0.1. Отличия от него
собраны в конце.

## Как это работает

```
Админка → POST /admin/messages
            │  одна транзакция: сообщение + получатели (message_recipients)
            ▼
         фоновая задача → pywebpush → push-сервис браузера → service worker → уведомление
            │
Студент ← GET /me/messages (инбокс — источник истины; push только сигнал)
```

* **Получатели — снимок.** При отправке в `message_recipients` записываются
  студенты, подходящие под адресацию в этот момент.
* **Досылка.** Новичок или студент, сменивший группу, получает сообщения своей
  группе, курсу или потоку за последние `MESSAGES_LATE_JOIN_DAYS` дней
  (по умолчанию 14). Личные сообщения (`students`) не досылаются.
* **Push не обязателен.** Не настроены ключи, устройство не подписано, сервис
  недоступен — сообщение всё равно в инбоксе. Подписки, которые push-сервис
  объявил недействительными (404/410), удаляются.

## Профиль студента

Студент указывает фамилию, имя и группу (раздел «Сообщения», с согласием на
обработку). Пароля нет.

* Профиль **привязан к устройству**: фронт присылает случайный ключ (тот же,
  что у обращений), бэкенд хранит его хеш. Повторная регистрация с этого
  устройства находит того же студента — так обновляется истёкший токен
  (60 дней, `STUDENT_JWT_TTL_HOURS`) и переносится профиль при смене группы.
* По одному ФИО чужой профиль **не получить**: другое устройство — другой
  студент. Обратная сторона: с нового телефона история прочтений начинается
  заново. Полноценно это решит вход через Moodle (`users.moodle_id` уже есть).
* Расписание по-прежнему открывается без профиля.
* Персональные данные — только `users.full_name` и группа.

## Важность

| | Push | «Ознакомлен» | Напоминание | Считается непрочитанным, пока… |
|---|---|---|---|---|
| `low` — для сведения | нет | нет | нет | не открыто |
| `normal` — обычное | да | нет | да | не открыто |
| `high` — важное | да, не исчезает само | да | да | не нажато «Ознакомлен» |

Прочитано (`read_at`) и ознакомлен (`acknowledged_at`) — разные события:
первое ставится при открытии, второе — кнопкой.

## Напоминания

«Напомнить» в деталях сообщения отправляет push тем, кто не прочитал, а у
важных — тем, кто не подтвердил. Не чаще раза в `REMIND_COOLDOWN_HOURS`
(6 ч) на сообщение, иначе 429.

## Push и PWA

* Фронтенд — PWA (`vite-plugin-pwa`, свой `frontend/src/sw.ts`): манифест,
  иконки, прекэш статики, показ уведомлений, по нажатию открывается
  `/?message=ID`.
* Ключи VAPID: `docker compose exec backend python -m app.cli generate-vapid`
  → `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` в `.env` в корне.
  Фронт берёт публичный ключ из `GET /push/config`, своя переменная не нужна.
* **Нужен HTTPS** (на `localhost` работает и без него).
* **iPhone/iPad**: push только у приложения, добавленного на экран «Домой»
  (iOS 16.4+). В Safari раздел показывает, как это сделать.

## API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| GET | `/directions` | все | направления и их курсы |
| GET | `/push/config` | все | публичный VAPID-ключ; `null` — push выключен |
| POST | `/auth/student/register` | все | `{full_name, group_id, device_key}` → токен и профиль |
| GET | `/me` | студент | профиль и `unread_count` |
| GET | `/me/messages` | студент | инбокс |
| GET | `/me/messages/{id}` | студент | открыть сообщение, ставит `read_at` |
| POST | `/me/messages/{id}/acknowledge` | студент | «Ознакомлен» (только `high`) |
| POST / DELETE | `/me/push-subscriptions[/{id}]` | студент | подписать / отписать устройство |
| GET | `/admin/users?q=&course=&group_id=` | админ | студенты с профилем — для адресации |
| POST | `/admin/messages` | админ | отправить |
| GET | `/admin/messages` | админ | список с прогрессом прочтения |
| GET | `/admin/messages/{id}` | админ | получатели со статусами |
| POST | `/admin/messages/{id}/remind` | админ | напомнить |
| DELETE | `/admin/messages/{id}` | админ | скрыть у всех |

Адресация (`target`): `{type: "all"}`, `{type: "course", courses: [1]}`,
`{type: "direction", directions: ["ПИ"], courses: [2]}` (курсы необязательны),
`{type: "group", group_ids: [3, 4]}`, `{type: "students", user_ids: [...]}`.

Студенческий токен на `/admin/*` — 403, админский на `/me` — 403.

## Таблицы

`users`, `messages`, `message_recipients`, `push_subscriptions`, плюс
`groups.direction` (заполняется из названия миграцией и импортом Excel).

## Отличия от ТЗ

| ТЗ | Сделано | Почему |
|---|---|---|
| Студент находится по `(ФИО, группа)` | по ключу устройства | иначе любой, кто знает ФИО, читает чужие сообщения и жмёт «Ознакомлен» за другого; плюс смена группы не теряет историю |
| Получатели только на момент отправки | плюс досылка за 14 дней | иначе «прочитали 30 из 42» — это 42 зарегистрированных, а поставившие приложение позже не видят сообщение своей группе |
| Напоминание тем, у кого `read_at IS NULL` | у важных — кто не подтвердил | открыл, но не нажал «Ознакомлен» — тоже не подтвердил |
| `low` — тихий push | без push | iOS отзывает подписку, если push не показывает уведомление |
| `DELETE` удаляет сообщение | скрывает (`deleted_at`) | отметки «Ознакомлен» — подтверждение, их нельзя терять |
| `created_by FK users` | логин админа строкой | админ живёт в `.env`, не в `users` |
| Cooldown в `reminded_at` получателя | `messages.last_reminded_at` | одна отметка на сообщение; `reminded_at` у получателя тоже ставится |
| `VITE_VAPID_PUBLIC_KEY` | `GET /push/config` | ключ задаётся в одном месте |
