# Сообщения студентам — что нового

В приложении расписания появился раздел **«Сообщения»**. Методист может
адресно написать студентам и увидеть, кто прочитал. Для важных сообщений —
кто подтвердил, что ознакомился. Студенты получают push-уведомления на
телефон или компьютер.

Здесь — что умеет функция и как ей пользоваться. Как она устроена внутри
(API, таблицы, отличия от ТЗ) — в [06-messages.md](06-messages.md).

---

## Студенту

### Как начать получать сообщения

1. Выберите свою группу, как и раньше.
2. Откройте вкладку **«Сообщения»** в нижнем меню.
3. Укажите фамилию и имя, отметьте согласие на обработку данных и нажмите
   **«Получать сообщения»**.

Пароль не нужен: профиль запоминается на этом устройстве. Расписание,
карта и «Вопросы» работают и без профиля.

> Если вы поставили приложение позже, чем методист отправил сообщение своей
> группе, курсу или потоку, вы всё равно его увидите: приложение досылает
> такие сообщения за последние две недели.

### Сообщения

* На вкладке «Сообщения» в меню — красный бейдж с числом непрочитанных.
* Непрочитанные выделены полосой слева.
* Нажмите на сообщение, чтобы открыть его полностью, — оно станет прочитанным.

### Важные сообщения и «Ознакомлен»

У важных сообщений (перенос пары, сроки, обязательные мероприятия) есть кнопка
**«Ознакомлен»**. Методист видит, кто её нажал. Пока вы её не нажали,
сообщение отмечено **«Нужно подтвердить»** и учитывается в счётчике
непрочитанных, даже если вы его уже открыли.

| Метка | Значит |
|---|---|
| Новое | ещё не открывали |
| Нужно подтвердить | важное, нажмите «Ознакомлен» |
| Ознакомлен | вы подтвердили |

### Уведомления

В карточке **«Уведомления»** вверху раздела нажмите **«Включить»** и разрешите
уведомления в браузере. Новое сообщение придёт как обычное уведомление
телефона, нажатие на него откроет сообщение в приложении.

* **iPhone / iPad**: уведомления работают, только если приложение добавлено на
  экран «Домой»: в Safari «Поделиться» → «На экран Домой», затем открыть
  приложение с иконки. Нужна iOS 16.4 или новее.
* **Android, компьютер**: Chrome, Edge, Firefox — прямо из браузера.
* Если уведомления запрещены в настройках браузера, приложение подскажет, что
  их нужно разрешить.
* Без уведомлений сообщения всё равно появляются в разделе — просто без сигнала.

## Методисту

Раздел находится в админке: меню в шапке → «Администрирование расписания» →
вкладка **«Сообщения»**.

### Отправить сообщение

Нажмите **«Новое сообщение»** и заполните:

**Заголовок и текст.**

**Важность:**

| | Уведомление | «Ознакомлен» | Напоминание |
|---|---|---|---|
| Для сведения | нет | нет | нет |
| Обычное | да | нет | да |
| Важное | да, не исчезает само | да | да |

**Кому:**

* **Всем** — все студенты с профилем;
* **Курсу** — один или несколько курсов;
* **Потоку** — направление (ПИ, ПрИ, БИ), при желании только на выбранных курсах;
* **Группам** — отметить нужные группы;
* **Студентам** — найти конкретных людей по ФИО.

Сообщение получат студенты, которые заполнили профиль. Если пока никто из
адресатов не зарегистрировался, сообщение всё равно сохранится, и они увидят
его, когда зарегистрируются (кроме сообщений конкретным студентам).

### Кто прочитал

В списке у каждого сообщения — полоска прогресса: «Прочитали 30 из 42», у
важных ещё «подтвердили 25». Нажмите на сообщение, чтобы увидеть каждого
получателя:

* **ознакомлен** — нажал кнопку (важные);
* **прочитал** — открыл;
* **не открывал**.

Переключатель **«Не прочитали»** (у важных — **«Не подтвердили»**) оставляет
в списке только тех, кто ещё не отреагировал.

### Напомнить

Кнопка **«Напомнить непрочитавшим»** (у важных — «неподтвердившим») отправляет
повторное уведомление только тем, кто ещё не отреагировал. Чтобы не надоедать
студентам, напоминать по одному сообщению можно не чаще раза в 6 часов.

### Удалить

**«Удалить сообщение»** скрывает его у всех студентов. Отметки о прочтении и
подтверждении остаются в базе.

## Администратору (настройка)

Без настройки всё работает, кроме push-уведомлений: сообщения видны только в
приложении.

1. Сгенерировать ключи: `docker compose exec backend python -m app.cli generate-vapid`.
2. Вставить вывод в `.env` в корне репозитория и выполнить `docker compose up -d`.
3. Приложение должно открываться по **HTTPS**, иначе браузеры не дают
   подписаться на уведомления (исключение — `localhost` при разработке).

Ключи генерируются один раз: новые ключи отключают все подписки.

Обновление существующей установки:

```bash
docker compose up -d --build
docker compose exec backend python -m alembic upgrade head
cd frontend && npm install
```

## Ограничения

* Профиль привязан к устройству: с нового телефона студент заполняет его
  заново, история прочтений начинается с чистого листа. Это решит вход
  через Moodle.
* Нет черновиков, вложений и ответов на сообщения: на вопросы студенты
  по-прежнему пишут через «Вопросы».
* Push-уведомления пока не проверены на боевом HTTPS-сервере с реальными
  телефонами — это нужно сделать перед запуском.
